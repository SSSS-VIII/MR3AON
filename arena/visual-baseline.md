# 竞技场实时视觉基线

这一版已接通原客户端的实时取图、人物/陷阱识别、运动跟踪、短时避障和验收记录。它是CPU视觉特征加运动预测的基线，尚未训练检测网络或策略网络。当前能有伤连续跑过前三块，不能称为稳定无伤或完整竞技场自动通关。

## 运行

本机arena已准备并运行时，在仓库根目录执行：

```bash
./tools/run-arena-vision --seed 42 --map 1 --pin 1:1101 --boards 3
```

选关与版型仍走原生地图池；pin只用于复现实验。默认40Hz控制，达到目标板子位置、死亡、150ms观测过旧或验收读取停止时结束。结束恢复原暂停选关菜单，没有新增游戏内选项。Ctrl+C同样暂停并收尾。原P/K/S输入与原游戏界面保留。

输出默认在忽略目录`debug/arena-client/visual-runs/`，包含原图、识别覆盖图、逐帧`vision.jsonl`、独立`evaluation.jsonl`及`report.json`。`--observe-only`用于不发送操作的对照；日志区分建议动作与实际发送动作。

本机OpenCV安装在`debug/arena-client/vision-v1/python`，入口自动加入模块路径，没有覆盖主项目Python依赖；依赖清单为`tools/arena-vision-requirements.txt`。原客户端资源和Android构建依赖仍按原arena入口准备，未分发至Git。

## 感知与控制

- Android常驻RGBA捕获，不调用宿主桌面或Wayland合成器截图API。画面统一640×360；HUD不作为陷阱，原按钮图标用于辅助区分绳索/地面。固定小黑镜头尺度经原collider投影核对，不能拿飘带、跑步尘土连通框的高度当缩放。
- 当前识别金色/红色眼睛的飞行怪、蜘蛛、白眼弹跳球，以及近处绳线、桥面和断口。保留低置信未知前景，不能将它们全部当成已识别陷阱。放大怪物按眼部尺寸估计危险范围，弹跳球按完整球体估计。
- 连续帧关联对象，保留短时遮挡预测；先做图像去重，再以时间戳估计相对位置、速度、加速度和拟合残差。纵向参考绳/地面，避免把角色换边和镜头跟随当成怪物运动。短线性/二次模型之外，周期轨迹用1–6rad/s的正弦候选拟合；这些是有条件的预测，不保证在反弹或突变处准确。
- 人物状态由画面、已发送动作和原生动作时序共同维护：绳上/下、换边、一/二段跳升降、接地及滑铲。`vision-motion-priors.json`来自原UI采样，包含随动作变化的Role碰撞箱；不改游戏物理。
- 决策器比较约0.76秒内不动、跳跃、换边、绳下返回后跳跃、滑铲的路径。陷阱几何与运动均来自画面。运行时不向策略传入地图/板子ID、原对象坐标或真实动作状态；选关和验收的内部数据独立保存。
- 原键盘通过Android注入，K/S短按80ms、地面滑铲S保持500ms。观测年龄和一个原渲染帧的输入时延先验参与外推；实际Unity GetKeyDown时间另行测量。

## 实机结果

完整日志在`debug/arena-client/vision-v1/`。以下均为章节1、关级1、map1、seed42，第一位置固定1101，其后仍由原池抽取11022、11032，进入11042时结束。没有跳过这三块，也没有在策略内识别板号。

最新一轮识别覆盖回放为`acceptance49/replay.mp4`，49.3秒；对应原图、逐帧估计和验收日志保留在同目录。

| 试跑 | 结果 | 累计掉血 | 结束血量 |
| --- | --- | ---: | ---: |
| run46 | 连续三块有伤通过 | 1140 | 3947 |
| acceptance48（正式入口） | 连续三块有伤通过 | 780 | 4313 |
| acceptance49（补顶部小蜘蛛检出/人物站姿对齐后） | 连续三块有伤通过 | 1560 | 3527 |
| run47-no-action | 同选关、同种子不操作对照，三块存活 | 1860 | 3220 |

累计掉血由逐渲染帧血量下降累计，恢复血量不会擦除受伤记录，所以它与开始/结束血量差不同。`passed`只表示无伤通过，`passed_with_damage`明确表示有伤；高血量下的存活不能单独作为避障效果证明。

这一小组中控制器的总掉血低于不操作，但表现不稳定，也没有多种子统计保证。以run46拆分，蜘蛛板180对780、直线乌鸦板300对840、混合板660对240；第三块的控制反而增加伤害。开发过程中曾完整无伤通过蜘蛛/乌鸦板，最好连续两块无伤，但后续改动后的重复无伤验收仍有失败，不能把历史最好成绩当成当前稳定能力。

run46中原游戏渲染约60FPS；取图中位3.75ms/P95 5.21ms，感知及决策中位16.81ms/P95 24.57ms，截图请求到Unity GetKeyDown中位37.93ms/P95 47.06ms。44次发送均被Unity输入看到。此时延不含截图前的显示帧年龄，也不等于角色物理动作已经生效；原按键确认本身约0.61ms。

暂停标注工具还核对了一个实际蜘蛛画面：两只可见蜘蛛都检出，中心与原对象投影相差约0.55/2.87px；人物估计中心与原Role bounds中心约差1px。这只是单帧对齐检查，未测全类别mAP。原图与原collider标签保存在`labels-spider/`。

## 标注和动作校准

```bash
.venv/bin/python tools/arena_snapshot_labels.py
.venv/bin/python tools/arena_motion_probe.py
```

前者暂停、隐藏菜单，保存640px原图和原角色/敌人的真实投影collider；后者在安全开头测原动作，生成候选运动先验。两者均只控制arena，结束恢复暂停菜单。标注不能直接作为纯视觉策略的运行时输入。动作数据说明见[基础参数](parameters.md)。

## 未完成

2. 旋转机关、隐藏刃、激光、墙体等尚未完成可靠识别。地面测试曾跨过首个断桥，但整块地面板仍失败；连接处和复杂支撑尚须验证。
3. 检出范围和形状仍是视觉估计；需要用原collider批量标注训练轻量检测器，量化漏检及轨迹误差，再训练/替换结构化决策器。未做完整训练、回档搜索或板子标准跑法。

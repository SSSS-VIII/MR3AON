# 按名字彻底关闭 Waydroid 后台

## 现象 / 需求

关闭 Waydroid 窗口不会结束 Android 后台，用户需要不接触实例编号和 ADB 的关闭入口；随后要求创建并打开 `xiaoli`。

## 原因

run 只有启动/配置/检查入口。设备层的 stop 为故障恢复保留 root manager，不能直接作为释放后台的操作；旧底层 stop 又刻意跳过默认实例的包管理器服务。首次创建 xiaoli 时还发现 session 就绪早于 DHCP 地址分配，原就绪检查会过早失败。

## 改动

- 新增 `./run [名字] --stop` 和设备层 `shutdown()`，取得同名排他控制权后停止窗口、Android 会话、用户服务和对应容器管理服务。main 关闭包管理器的 waydroid-container，其它名字只关闭各自服务。
- 保留账号配置、Android 数据、任务状态及日志；同名再次启动继续复用。运行中的同名脚本或录制占有控制权时拒绝关闭，需先退出该脚本。启动/配置/检查/关闭参数互斥。
- 恢复用 stop/restart 的轻量语义不变。显式关闭也不全局杀进程、不清空其它实例网络。
- 实测尝试停止独立 ADB server 会遇到旧 server 不响应退出；最终保留宿主 ADB 基础设施，只断开本实例设备，清理最多等待 5 秒，失败也不阻塞已完成的 Waydroid 关闭。
- 就绪检查等待本实例取得 DHCP 地址后再绑定连接，避免首次创建或冷启动过早返回失败。
- 按用户要求建立持久名字 xiaoli 并打开窗口。运行数据位于 `.mr3a-instances/xiaoli`，账号和任务为空，不复制主账号；设备截图已成功。

## 验证

- 实例注册、运行路径、工具路由、关闭互斥、关闭不启动设备、默认/次实例后台目标及冷启动等待：35 项针对性测试通过。
- small 实机关闭和重复关闭成功，用户服务及系统管理服务均不再 active；随后同名检查启动、截图、再次关闭成功，配置散列不变。small 最终保持关闭。
- main 和 xiaoli 在上述操作前后的 Android boot_id 均未变化，截图均有效；xiaoli 最终保持打开。未关闭正在使用的 main；默认停止服务路径通过 mock 验证。
- CLI help 与 diff 空白检查通过。本轮未重跑全量业务测试，既有 5 项失败仍见 current-work。未操作游戏，未改账号密码；未完成鬼族改动不纳入提交。

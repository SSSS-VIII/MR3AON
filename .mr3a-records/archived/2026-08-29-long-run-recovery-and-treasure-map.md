- 已对所有 `my_3v3_kn_*` 点击序列接入校准状态；Python 静态编译、格式检查及欠账计算检查通过，未启动游戏。

## Agent 持久化任务状态框架

- 新增 Agent 自有状态文件 `deps/bin/config/agent_task_state.json`，按任务 `entry` 保存顶层及节点级 `enabled` 与 `valid_until`；Agent 启动加载时即创建缺失文件，后续采用临时文件加原子替换写入。
- Agent 接管 PiCli 计划时读取状态文件，并在候选队列中标记当前不可执行项；禁用项不会被删除，原始名称、入口和完整 pipeline override 均会保留。
- 候选队列只跳过当前禁用项。若只剩禁用候选，Agent 进入等待，不会误报计划完成；有效期结束或每日 05:00 重载后，候选项可重新恢复执行。
- 每日 05:00 只作为状态到期边界，不使用后台定时器。真正的文件重载、过期清理和候选重建仅发生在 Agent 即将提交下一项的调度安全点；当前业务任务跨过 05:00 时不会被打断。若 Agent 正处于无业务任务的调度等待节点，则等待会在最近有效期或 05:00 中较早的时间点返回调度。
- 任务若在 05:00 前开始、05:00 后完成，完成节点按完成时刻登记到下一个 05:00；随后调度安全点清理旧周期状态时会保留这条新完成记录。
- 完成登记同时将当前 PiCli 任务实例保留为 Agent 内部的下一周期休眠候选，不会直接提交给 Maa；到有效期后只在任务结束/调度等安全点恢复，解决已执行候选被队列消费后无法跨日恢复的问题。
- 新增 `SetManagedTaskPersistentState` CustomAction。默认操作当前 Agent 任务，也可显式指定 `entry`；传入 `node` 时只覆盖该任务类型下的对应流水线节点。`valid_until` 支持 ISO 时间、`next_daily_reset`，以及默认周一 05:00 的 `next_weekly_reset`。
- 同一 PiCli 计划可包含多份配置不同但入口相同的任务。每份候选都保留自己的原始 override；节点级持久化状态会覆盖所有同入口实例，状态不存在或过期后则分别恢复各自的 PiCli 配置，不会在实例之间串配置。
- 通用框架先以独立提交落库，具体游戏任务的首轮接入记录如下。

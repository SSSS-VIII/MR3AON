# Agent 挂起任务与启动总时限收尾

## 本轮完成

- Agent 已接管 MaaPiCli 的业务任务队列，任务结束前提交下一项，避免 Agent 在 task 结束后被回收。
- 调度器保留每个任务实例的 PI option override；恢复或挂起后重排不会丢失原配置。
- 错误重启完成启动流程后先交回 Agent 调度，到期任务可以在恢复原任务前插队。
- 通灵巡逻支持挂起：新开始巡逻按 2 小时估值，已在巡逻时使用流程原有 OCR 倒计时；奖励可领时自行领取并重新检查忍阶任务。
- 忍村试炼支持每 4 小时挂起，Agent 维护本次任务观测到的最大剩余挑战次数；最大值达到过 3 时不打第四候选。
- 藏宝图任务连续运行 1 小时后，Agent 发出一次性让出信号；流水线仅在可安全退出的节点消费信号，将当前任务放回内部队列队首。
- 3v3 因开放时间不符而退出时，使用 `daily_times: ["13:00", "20:00"]` 登记固定时点。该入参为非 fallback 模式，存在时完全忽略 OCR 文本。

## 最新实机卡死结论

- 2026-08-28 22:45 开始的最新实机运行持续到 2026-08-29 01:09，一直停留在启动 task。
- 游戏已显示主页内容，但进程对点击无响应；`启动游戏点击主页设置` 约成功 7004 次。
- MaaFramework `timeout` 只统计单次 `run_next()` 中 `next` 持续全 miss 的时间。任意节点识别成功都会返回；JumpBack 后重新调用 `run_next()` 会创建新计时器，因此无法捕获“持续识别成功但游戏无进展”。
- 项目早已有 `LoopDeadlineArm / LoopDeadlineExpired`，使用 Agent 单调时钟按 `task_id + scope` 维护绝对截止时间，原用于每日悬赏组队等待。
- 启动流程已复用该机制：正常启动总时限 6 分钟，到期进入原有关闭游戏重试；业务任务的恢复启动总时限 2 分钟，到期再次 `RestartGame`。每次重启后都重新 arm。

## 边界与待验证

- 当前是“启动阶段总时限”，不是通用的画面无进展/重复节点 watchdog。
- `popup_watchdog.py` 只用于弹窗处理，且当前没有向 Agent 注册，不参与本次卡死恢复。
- 本轮按要求未运行新的游戏或自动化测试。待下次长时实机运行验证启动卡死重启和多挂起任务到期顺序。

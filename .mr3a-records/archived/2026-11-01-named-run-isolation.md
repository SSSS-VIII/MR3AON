# run 按名字启动与 Agent 完整运行隔离

## 现象 / 需求

用户要求外部只提供名字，默认 `./run` 保留当前配置和账号，`./run xxx` 独立复用另一套环境。全部 Waydroid 检查、ADB、日志、debug、奖励和任务状态都随名字绑定。继续为大小号协同和后续 dsh 接口打基础，本次不实现智能体服务或协同业务。

## 原因

旧 run-test 复制程序和主配置，会混入主账号输入；Agent 又切 cwd 到 assets，日志/奖励/缓存分散在共享位置。输入文本动作另有全局单设备发现，TUI 和孤儿回收按会话/TTY 或全局扫描，无法安全并行。

## 改动

- `run` 统一进入 `runtime.launcher`，只选择名字；main 复用 `deps/bin`，新名空任务配置，配置菜单单独保存账号密码。`test` 不再是特殊复制模式。
- 共用同一个已重编 MaaPiCli，通过目录参数定位每个环境；Agent 的绝对入口和资源路径写入小型 interface，不复制源码、二进制、动态库或资源。底层 CLI 功能在 MaaPiCli 的 `7fa3bf2c` 独立提交，控制器空句柄修复为 `f42934de`。
- 框架/Agent 日志、奖励图、deadline 截图、任务状态、元数据和学习题库均使用实例运行目录；主配置和 pip 设置保留，新环境不复制主账号完成状态。旧主奖励在正式接管取得控制权后合并，不丢冲突图；旧日志不删除。
- Agent 启动检查/恢复委托按名会话；输入文本动作统一设备选择。绑定设备不在线时失败，不选择其它可用账号。恢复更新自身 serial，不改变其它实例。
- 正常恢复只停止 Android 会话并复用已运行的 root manager；内部提权非交互，缺少宿主权限时明确失败，不等待隐藏密码提示。当前宿主已具备免密 sudo，本次未修改 sudoers。
- launcher 持有跨 exec 的控制租约，记录精确 PiCli PID。TUI 退出只结束该实例进程，孤儿回收按工作目录隔离，命名模式不做全局 socket 清理。
- `tools/run-* [名字]` 复用同一环境和账号，仅用 CLI 内存任务选择，不改保存的任务列表。同步 README、开发规则、运行环境和接口边界，停用旧 `.run-test` 做法但不删除其文件。
- 实例设备对象已提供截图和输入租约，后续 dsh 复用该对象即可，不另建端口/ADB 管理。未开发智能体服务、邀请或组队业务。

## 验证

- 名字/运行路径/绑定设备/TUI PID/真实 CLI 等针对性测试 27 项通过。
- `./run main --check`、`./run small --check` 通过；按名字获取两台真实 1280x720 PNG，主 PiCli 配置内容 hash 未变化。
- 实际执行 `./run small --configure`，显示独立空任务菜单，正常退出；同名第二次启动被控制租约拒绝。旧主脚本保持运行，未强杀切换。
- main / small 同时使用同一 MaaPiCli 和 Agent 执行只截图的测试夹具，分别写出框架日志、自定义日志、奖励 PNG 和任务状态；没有向游戏发送点击，也未加入日常列表。
- `InstanceSession('small').restart()` 实测成功，主 Android boot_id 不变、次管理服务 PID 不变，截图恢复。
- 含实机只读冒烟的全量测试：**107 passed、5 failed、79 subtests passed**。5 项均为已记录的既有失败（3 项双字段断言、悬赏商店路径、逆袭旧节点），本次未改这些断言掩盖问题。
- Python 编译、Shell 语法、diff 空白检查通过。鬼族代码和记录继续保留工作区，未纳入本功能提交；MaaUtils 的原有子模块改动未提交。

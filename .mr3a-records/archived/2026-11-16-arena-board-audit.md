# 疾风1–6关逐板清单与历史验收证据

## 需求与原因

用户要求后续每块板逐一筛查，优先第5、6关，第7关暂不测。原目录已经合并仅传送符入场不同的地图；不能再次把raw maps全部列出，也不能把同一板号的多个合法槽位丢掉。现有材料采集、运动探针、离线识别评分与真实策略回合混放在ignored目录，需要按证据语义分开。

## 改动

新增只读`tools/arena_board_audit.py`，不导入实例管理、控制桥、视觉运行器或GPU依赖，不执行游戏输入。默认扫描本地原目录及保存的actor报告，写JSON和简短概览，不增加游戏菜单选项。

- 直接沿用`gale-catalog-native.json`的canonical levels与已提交的传送符地图别名。保留原chapter/level/map/start/pins，并反查候选确实存在于原map group；按StageID建立首轮去重清单，所有原map/slot上下文单列。
- 从原Stage配置计算布置随机/固定及动作随机证据，保存原地图难度、速度、坡段、入口风险和源文件SHA。固定布置不代表敌人AI/动作完全确定；静态合法入口不等于所有种子可安全到达。
- ItemBossController32、原controllerDataID和循环块识别Boss机制；无配置敌人且具有原币堆Start2/End101的布局归奖励机制；ItemSpecialTaskStart43单列特殊任务。Boss另保存原CfgEndlessGaleBossInfo，不把原1血改动等价为已自动通过。
- 同map连续普通槽位组成多板批次，每个目标槽固定pin，遇到Boss/奖励/特殊任务停止分组。共享板首轮只算一次；为衔接而重复的板明确标记，不伪称新增覆盖。CLI参数仅是测试工具入口，不改变游戏玩法或运行配置。
- 真实actor证据必须有setup、原initial、report actions与board_entries；采集、observe-only和缺少该证据结构的结果排除。旧报告没有goal时，只有实际进入后续板才证明前板完成；最后仅进入的板不能因为报告整体passed而算完成。
- 无伤仅在整回合完成、原damage=0、had_damage=false、原god=false且无评估错误时记入。多板损血保留整回合总数，不擅自分摊给每块板。历史证据与当前源码证据分别输出。通过AST读取运行器的完整sources常量，不导入GPU代码；只有清单完整且每项SHA匹配才计当前源码证据，旧报告仅部分文件相同不算。该SHA匹配仍不保证权重相同，报告继续携带原detector信息。

只读用法：

```bash
python tools/arena_board_audit.py \
  --output debug/arena-client/yolo/finetune/rope-recovery-v37/board-audit-tool.json
```

`--levels 5 6`可只输出高关目录；`--reports-root`可限定历史报告目录。所有输入和输出均为本地文件，不启动实例。

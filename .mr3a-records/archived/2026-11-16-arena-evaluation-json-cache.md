# 缓存不可变血降JSON以避免评估工具阻塞Unity主线程

## 现象与原因

v70密集板捕获150–164ms尖峰主要发生在Lua接收请求之前：等待接收约103–126ms，EOF等待25–44ms，ReadPixels仅1.5–2.2ms、传输约.6–1.3ms。评估每.1秒调用原纯Lua json.stringify，并重复递归最多16份已经完成的碰撞几何；最近一次还通过last_health_drop再编码一次。原实现随受伤次数累积增加主线程负载。

v73在已暂停arena使用保存的原16事件，仅替换局部校准变量、不改原HP/物理：原序列化16事件中位24.318/max99.405ms，缓存原型.663/max1.310ms；完整解析比较事件与其它字段语义一致。0/1/4/8/16事件和全部原样本保留，不能用此单项证明所有截图长尾根因。

## 改动

vision_eval增加encode_vision_evaluation：已完成事件按Lua表身份缓存JSON，轻量实时字段每次新编码，再拼接原数字键对象形式的health_drops和原last_health_drop，不丢字段、不去重删事件、不把原证据提供给演员。事件源只在实际血降创建、追加后不再修改；缓存仅保留当前历史与last引用的事件，轮换淘汰，新评估重置。原每帧血量/原输入采样、16事件上限、.1秒写入周期均保留。

周期writer的采样/编码/写盘整体纳入pcall，失败保留visionEvalError；新增上一次writer_timing（sample/serialize/write/bytes）仅供事后检查，不进入演员。没有改原游戏GC、物理、HP或避让决策。

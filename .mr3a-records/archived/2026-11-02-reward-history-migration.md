# 奖励列表出现「历史_每周逆袭悬赏」

## 现象 / 需求

主环境奖励列表又多出「历史_每周逆袭悬赏」。不应把内部迁移备份作为游戏奖励分类展示，需要清理当前多余项并修复来源。

## 原因

命名实例接入时，主环境把 `assets/debug/reward_shots` 合并到 `deps/bin/debug/reward_shots`。旧迁移代码遇到同名、不同内容的截图，会在奖励根目录下建立 `历史_<原分类>` 保存较旧版本，并登记到奖励列表。

迁移每次正式启动都会执行，没有完成标记。旧源图片一直保留，日常清理后的截图可能再次导入，发生同名冲突时又生成历史分类。历史备份又在奖励清理范围内，图片被清理后留下真实空目录；前次幽灵分类修复刻意保留正常空分类，因此不能解决本次有真实空目录的情况。

实查 `历史_每周逆袭悬赏` 为 0 张图片的空目录，registry.json 确实登记了它；不是奖励流水线新增了一个业务分类。

## 改动

- 冲突旧图保存在实例自己的 `debug/reward_shots_archive/<原分类>/`，内容哈希命名，位于奖励列表及日常截图清理范围之外；较新图保留在正常分类，旧源不删除。
- 完成首次合并后写 `debug/legacy_rewards_migrated.json`，后续不再导入旧源，避免重新带回清理过的旧截图。
- 兼容旧版本：把奖励根下现有 `历史_*` 内的文件保留到外部归档，清除迁出后的空目录，并按真实业务目录重建登记。即使旧源已不存在，也会修复旧历史分类；正常业务空目录保留。
- 当前 main 已有明确的旧迁移记录，因此补记迁移完成，再执行分类修复，不重新导入旧图。只修改本地奖励目录及登记，未中断脚本、未操作游戏。

## 验证

- `PYTHONPATH=agent .venv/bin/python -m pytest tests/test_named_instances.py agent/tests/test_reward_shots.py -q --tb=short`：24 passed。
- 覆盖源/目标两种时间顺序的冲突保留、重复运行不重复归档、日常删除后不重导入、旧源不存在时历史空目录清理及非空目录图片迁出、业务空目录保留。
- 当前 main 清理前后 9 张奖励 PNG 的相对路径及 SHA256 完全相同；历史分类目录和登记均已移除，正常六类保留。此次历史目录本来为空，没有需要迁出的历史图片。
- `git diff --check` 通过。当前目录修复已落地；正在运行进程的分类读取按目录有效性过滤，界面刷新后应不再显示该项，未宣称已人工检查 TUI。后续启动会加载迁移修复，未重启游戏进行验证。

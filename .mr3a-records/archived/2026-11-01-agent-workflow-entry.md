# 固定 Agent 读取入口与开发流程

## 现象 / 需求

用户不希望每次会话重新介绍项目开发流程、记录目录和提交习惯，需要能直接发现并读取的持久入口。

## 原因

详细历史存在 `.mr3a-records/`，但此前入口没有把长期流程、当前交接和相关归档明确串起来；Agent 也曾只读公开 README 或把工作流理解为 GitHub Actions。仅依赖聊天历史不足以交接。

## 改动

- 根目录 `AGENTS.md` 增加强制开工读取顺序，明确用户所说的记录目录即现有 `.mr3a-records/`。
- 新建 `workflow.md`，集中记录本地开发与收口步骤、定制 MaaPiCli、隔离测试、调度回调约束和双字段兼容等规则，并链接历史依据。
- README 链接流程页，区分流程、交接、roadmap、环境和归档的职责。
- 按用户最终明确的流程修正：通过记录、Git 历史与代码交叉了解项目；整理工作区按功能独立提交已完成项，每个提交带对应记录和测试。鬼族等未完成项保留工作区，禁止打包提交。

## 验证

- 对照 OpenAI 官方 Codex 文档确认 `AGENTS.md` 是持久仓库说明的发现入口；普通 Markdown 依靠入口指引读取，而非自动全量加载。
- 核对本文流程与既有开发归档，不改业务代码、不启动游戏。
- 提交前检查文档相对链接和 `git diff --check`；本次仅文档变更，沿用已记录测试基线。

# 每周逆袭阶段1：修复列表页 S 奖励次数停判

## 现象 / 需求

已经添加列表页奖励上限判断，但 main 每周逆袭仍反复进入阶段1，S 奖励次数用完后继续等队伍、刷新。

## 原因

对照 `20336e3`、阶段持久化记录、流水线、2026-11-02 运行日志及实际截图确认：之前只接入判断入口，却沿用了准备页的 OCR 区域 `[570,50,360,50]` 和「次数上限」文案。列表实际在 `[100,145,510,55]` 显示「剩余奖励次数：逆袭A:2/逆袭S:0/逆袭SS+:0」，旧区域识别到的是顶部「挑战、速道」等文字。

此外旧 And 的第一项要求识别「刷新」，按钮进入倒计时后第一项就失败，第二项不再执行。`maafw.bak.2026.11.02-06.28.36.939.log` 中 06:27:20～06:28:36 的 224 次失败，198 次停在倒计时（500～504 秒），另 26 次虽认到刷新，仍在错误 ROI 读不到「次数上限」。自定义日志反复应用阶段1筛选，持久化状态没有阶段1完成登记，与此吻合。

## 改动

- 用列表底部稳定的「我的逆袭悬赏」确认页面，取消刷新文字前置条件。
- 列表奖励行匹配 `逆袭S\s*[:：]\s*0(?!\d)`，仅 S 剩余次数为 0 才走已有阶段1完成、周日重置的持久化链。不把 A/SS+ 用完或 S:10 当作 S:0。
- 阶段2/3应用筛选时显式关闭阶段1列表停判，避免 NodeOverride 沿用阶段1启用状态后反复触发已完成阶段。
- 保留准备页「次数上限」兜底、阶段2/3概率掉落停判及各自重置时间。
- 加入实际列表原图、原生 MaaFramework OCR 回放和阶段/正则回归；原生回放使用独立进程，避免其它 Agent 单测切换 MaaAgentServer 的全局 SDK 状态干扰，不连接设备。

# 截图与跑图录制按实例名字路由

## 现象 / 需求

用户要求外部只提供名字，所有检查和设备操作归属于同一环境。run 已接入，但旧截图/录制工具仍裸调用全局 adb，输出到共享 debug，可能误操作主账号。

## 原因

两个工具各自执行 adb 命令，未复用命名设备对象；录制也没有与脚本互斥的控制租约。

## 改动

- `tools/adb-screencap [名字] [文件名]` 使用 `InstanceSession`，保存到该实例 `debug/adb-shots`，截图不抢占输入控制权。
- `tools/record-3v3-parkour [名字]` 使用同一设备对象并持有控制租约，输出到该实例 `debug/3v3-record`。同名脚本运行时不抢控制；要求交互终端，错误明确返回。
- 录制的按键、时间差与 +60ms 扣减算法不变。设备对象缓存已绑定目标，就绪/恢复时刷新；避免每次按键重新启动 Waydroid 状态查询，保持背靠背双击的传输路径。
- launcher 的程序能力检查也在实例 cwd 中执行，保证初始化诊断的归属一致。
- 用法同步到运行环境文档；智能体仍应复用设备对象，不借用这些终端工具做自己的 ADB 管理。

## 验证

- 3 项工具测试通过：截图使用名字及其输出目录且不争抢租约、录制持有正确名字的租约、绑定后的输入复用目标而不逐次轮询 Waydroid。
- 实际执行 `tools/adb-screencap small instance-check`，PNG 保存于 small 的 debug/adb-shots，未写入主环境。
- 录制 help、Python 编译、Shell 语法和 diff 检查通过。录制输入路由用 mock 验证，未在真实游戏中发出录制点击；时序算法未改。
- 全量实机只读验证：110 passed、5 failed、79 subtests passed；5 项为既有业务路径/兼容字段断言问题，详情见 `current-work.md`。鬼族内容未纳入提交。

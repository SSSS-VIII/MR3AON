# 竞技场客户端数据提取

目标是建立本地跑酷模拟所需的资源集。已交付离线资源导出工具和 [可操作本地模拟器](竞技场本地模拟器.md)；自动竞技场操作仍待开发。第一版物理模型以用户指定的小黑基础动作为基准。

## 本地数据

本次官服 main 的结果保存在仓库忽略目录 `debug/arena-client/dataset/`：

- `client.json`：APK 来源、元数据摘要、热更新版本标记和提取范围。
- `resources.jsonl`：每个资源包的来源（APK / dynamic）、SHA-256、真实资源路径和导出项。
- `assets/assets/gameresources/binarydatas/leveldata/`：保持客户端内部路径的 Stage JSON、Level 原始 bytes，以及额外生成的 `.bytes.json`。
- `objects/`：选择预制体时额外导出的组件、变换、碰撞体和脚本结构，引用保留原始 path ID。

资源、配置包、Lua、安装包和恢复出的资源解密材料都只留在本地忽略目录，不随工具提交。工具不读取账号登录配置，不连接 Android，也不调用游戏操作。

## 运行

先按 `.mr3a-records/test-environment.md` 和 `runtime.InstanceSession` 确认实例身份。已占用的实例无需接管：宿主机只读检查其安装目录和外部资源目录即可，不使用另一台设备的包代替官服。当前 main 的宿主数据根为 `~/.local/share/waydroid/data`；其它名字应根据现有实例后端确认，不能用此路径猜测或重分配设备。

使用独立工具环境，不改 Agent 的依赖：

```bash
python3 -m venv debug/arena-client/toolenv
debug/arena-client/toolenv/bin/pip install -r tools/arena-requirements.txt
```

由本机包安装路径取得 `base.apk`，将客户端外部 `files/DynamicContent` 作为 `--dynamic`。宿主文件需要 root 读取时，只对离线导出命令使用已有的 `sudo -n`；不修改源目录权限。示例中的变量由调用者填写实际文件路径：

```bash
debug/arena-client/toolenv/bin/python tools/arena_client.py \
  --apk "$arena_apk" --dynamic "$arena_dynamic" \
  --output debug/arena-client/dataset \
  --bundle 6d943555239894308f92b17fa1c0a384.ab \
  --bundle 9fc1b8b919e13b3a7b3dcb76ebfd07e6.ab
```

以上资源名仅对应本次客户端，版本变化后应重新索引。工具从该客户端元数据中匹配资源包密钥并校验 Unity China 签名，不打印密钥。`--key-file` 可复用本地已恢复的资源密钥。未指定 `--bundle` 时读取所有本地包；`--index-only` 只生成真实资源路径索引，不导出资产。`--assets` 为筛选资源路径的正则。

同名包优先读取热更新目录，不存在才回退安装包。读取文件期间检查 stat，并检查整个操作前后的 PatchVersion；发现更新变化则报错，应在更新完成后重新导出。一次运行重建 `resources.jsonl` 和 `client.json`，已有资产文件不会自动删除；改变筛选范围时应使用新的输出目录，以免把旧文件计入新范围。

## 数据语义与模拟边界

Stage 的 `_levelBlockInfos` 保留分组；每个块包含 `_pointStart`、`_pointEnd`、`_groundType`、`_ninjaSpeed` 和 enemy/item/npc 列表。敌人与物品保留 `_localPosition`、旋转、缩放、类型编号及自定义结构。必须保留局部坐标与段落坐标的区别，不能直接把资源坐标当作拼接后的一局世界坐标。

Level 的 `.bytes` 是 .NET NRBF。`arena_nrbf.py` 只解析记录、类型、数组和引用，不加载程序集、不实例化客户端类型、不执行 BinaryFormatter。JSON 中保留 `$type`；枚举保留 `value__`。列表按 `_size` 去掉容量尾部。Level 中 `_stageRandomGroup`、`_loopRandomStage`、`changeToStageList`、难度、候选权重和 `_stageSpeed` 可用于后续拼图规则核对。

当前导出的 Endless / Endless_Gale / SingleEndlessReserved1 是客户端资源池。存在文件并不等于当前服务器会选中它；保留模式编号，后续须确认当前竞技场的入口映射、候选选择、随机种子、速度覆盖及障碍运动逻辑。不要按文件名或 Stage ID 排序拼出一局，也不要丢弃速度 0、负数或其它特殊值。

`_ninjaSpeed` 是客户端原始数值，世界单位、时间步长以及 Level / 状态对速度的覆盖尚需核实，不能直接写成像素/秒。Unity 项目全局 Physics2D 的默认重力也不能当作小黑自己的 `Gravity`。

小黑的起跳速度、重力、二段跳重置、下翻状态转换/速度/持续时间、输入窗口和各状态碰撞体必须由行为实现或受控实测核对。当前工具已提取序列化参数，运行时验收仍待完成，不能据关卡 JSON 宣称模拟器已与客户端一致。

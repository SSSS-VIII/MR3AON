# 项目简介

面向开发者的 MR3A 项目概览，涵盖技术栈、编码约定和已知限制。如果你打算贡献代码或深度定制脚本，建议先读这里。

## 技术栈与流程

本项目基于 **MaaFramework** 开发。脚本核心在 **Pipeline**：用多个节点 JSON 描述状态转移；典型节奏是 **先识别、再点击**，尽量避免 `DirectHit` + 点击这类「未识别就操作」的写法，以降低误触风险。

## 任务封装与出错回退

MR3A 对任务做了统一封装，并采用 **`jump_back`** 机制：流程中若节点出错，可跳回任务入口进行重试，而非直接中断整个流程。

## 配置约定

不鼓励在节点上长期堆叠 `rate_limit: 0` + `pre_delay: 0` + `post_delay: 0` 这类「零节流、零间隔」写法。仅非动作节点（无 `action` 的纯识别/跳转节点）适合把 `pre_delay` / `post_delay` 配成 `0`，其余节点请保留合理节流与间隔，避免打满模拟器与识别。

## 已知限制

3v3 跑图当前以固定延时点击为主，对不同延迟、不同网络环境的设备兼容性一般。若你环境差异较大，需自行微调或接受偶发偏差。

## 数据同步架构

采用**黑板体系**，`assets/remote/game-meta.json` 为唯一数据源，各知识源独立运作。

### CI 侧

```
BWiki ──[update_codes]──> remote/game-meta.json ──[sync_kdocs]──> 金山文档
```

- **`update_codes`**：定时从 BWiki 爬取每周兑换码，写入黑板。
- **`sync_kdocs`**：监听黑板变更（push / CI 完成 / 手动），同步全量键值至金山文档 `GameMeta` 表。

### 客户端侧

| 版本 | 路径 |
|---|---|
| 旧版 | jsDelivr 读取仓库 `remote/game-meta.json` → `RemoteJsonOverrideExpected` → 合入流水线 |
| 新版 | `DownloadGameMeta` 从金山文档拉取 → 本地缓存 `resource/data/game-meta.json` → `LoadGameMetaOverride` 读缓存合入流水线 |

新版离线容灾：金山不可达时复用本地缓存，首次无缓存自动写入兜底数据。

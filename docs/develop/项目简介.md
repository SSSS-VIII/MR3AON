# 项目简介

面向开发者的 MR3A 项目概览，涵盖技术栈、编码约定和已知限制。如果你打算贡献代码或深度定制脚本，建议先读这里。

## 技术栈与流程

本项目基于 **MaaFramework** 开发。脚本核心在 **Pipeline**（多个节点 JSON 描述状态转移）与 **Agent Custom**（自定义识别、点击等扩展动作），典型节奏是 **先识别、再点击**，尽量避免 `DirectHit` + 点击这类「未识别就操作」的写法，以降低误触风险。

## 任务封装与出错回退

MR3A 对任务做了统一封装，通过全局 `on_error` 搭配 **`jump_back`** 机制：节点出错时跳回任务入口重试，而非直接中断整个流程。

## 配置约定

不鼓励在节点上长期堆叠 `rate_limit: 0` + `pre_delay: 0` + `post_delay: 0` 这类「零节流、零间隔」写法。仅非动作节点（无 `action` 的纯识别/跳转节点）适合把 `pre_delay` / `post_delay` 配成 `0`，其余节点请保留合理节流与间隔，避免打满模拟器与识别。

## 已知限制

3v3 跑图当前以固定延时点击为主，对不同延迟、不同网络环境的设备兼容性一般。若你环境差异较大，需自行微调或接受偶发偏差。

## 游戏元数据获取

CI 定时从 BWiki 抓取兑换码写入 `assets/remote/game-meta.json`，触发 `sync_kdocs` 同步至金山文档。客户端通过 `DownloadGameMeta` 拉取到本地缓存，`LoadGameMetaOverride` 读取并合入流水线。金山不可达时复用本地缓存，首次无缓存自动写入兜底数据。

## 老板娘问答

答错学题模块。匹配流程读本地 `老板娘问答.json` 题库；回答错误时**追加**写入该文件，同步上传至共享金山文档「老板娘问答」表。金山侧仅写不读，开发者发版时手动审批题库增量，合并入新版发布。

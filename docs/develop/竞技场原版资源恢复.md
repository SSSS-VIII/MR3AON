# 竞技场原版资源恢复（开发中）

目标是用于视觉训练的游戏环境，需要原版模型、骨骼动画、特效、镜头、状态碰撞以及随机板子的行为一致。已完成一组原始资源恢复、小黑跑步动画独立渲染，以及部分运行时方法/碰撞分支定位；尚无可验收的竞技场模拟器。旧 [动作参数调试器](竞技场本地模拟器.md) 不可用于生成训练集。

## 原始资源保全

`tools/arena_fidelity_assets.py` 复用客户端读取器，按当前AssetBundles清单闭包加载依赖。闭包允许客户端实际存在的循环引用；应将全部依赖一起加载，不能将返回列表解释为无环拓扑顺序。

```bash
debug/arena-client/toolenv/bin/python tools/arena_fidelity_assets.py \
  --apk "$arena_apk" --dynamic "$arena_dynamic" \
  --manifest debug/arena-client/decoded/dynamic-AssetBundles-2.json \
  --key-file debug/arena-client/raw/bundle-key \
  --root f01f901904c917350202578593240b59.ab \
  --root f34d7058023b2dd5892cebdd3570e146.ab \
  --root ccc594ffc8050a6b867f86481a9b4c60.ab \
  --root 3b61efefec46ca07b2e0fea14332e4a3.ab \
  --root 226c45fc0cc73f0ea2572f9ccf6fea3f.ab \
  --root ecff2476358ccc1a83b57ead9632c5be.ab \
  --output debug/arena-client/fidelity-recovery
```

源路径确认与工具依赖见 [数据提取](竞技场客户端数据.md)。以上根包对应本次版本的小黑本体、SkeletonData/atlas/texture、空中板子、镜头以及共享烟尘/动作特效，不代表已穷尽竞技场主题、敌人和所有动态加载资源。换版本必须重新核对清单和根包；不同提取范围请使用新输出目录。

输出均在忽略目录：

- `serialized/`：解开客户端外层封装/资源加密后的原始SerializedFile及resS字节；AssetRipper等工具的恢复输入。
- `object-payloads/`、`type-trees/`、`binary-fields/`：全部组件类型的原始对象、结构和二进制字段，不丢弃粒子、动画、Shader、Mesh或相机。
- `text-assets/`：无UTF-8替换的原始字节，包括Spine二进制骨骼和atlas。
- `texture-previews/`：供检查的PNG；压缩纹理原件仍以serialized文件为准。
- `objects.jsonl`、`recovery.json`：原始包来源/摘要、对象路径、依赖闭包、类型统计、实际骨骼头部版本和错误。遇到缺失依赖、冲突原件、更新中途变化立即失败；对象解析/纹理解码失败记录后以非零退出。

## 当前证据

六个根包闭包86包，导出无错误，保全95张Texture2D、231个Shader、62套粒子系统、105个Material、20个AnimationClip、11个AnimatorController及镜头/碰撞等原始对象。共享包还包含其它角色/首领资源，不应把闭包所有资产算作已还原的小黑效果。

小黑`nijia_black_5.25.skel`头部实际版本为Spine **4.0.21**，文件名的5.25不是运行库版本。配原atlas与1024×1024纹理，官方Spine Viewer 4.0.64能解析92段动画；选择皮肤1后原始run动画成功渲染。证据：`debug/arena-client/spine-probe/verified-run.png`及`animations.json`。该预览没有背景、游戏状态机、碰撞或Unity材质，因此不作游戏画面一致性验收。

解析的动画片段时长：run=0.5s、jump≈0.366667s、roll2≈0.066667s、fall_roll≈0.4s、slide=0.5s。它们是动画时间轴长度，不能等同于跳跃滞空、下翻状态持续时间或输入窗口，客户端可能循环、缩放播放速度或提前切换。

## 导出工程的缺失

AssetRipper 2.0.0已从原始serialized生成本地工程：`debug/arena-client/restored-unity-project/ExportedProject`。它是资源恢复产物，**不能称作已还原游戏**：23/23个C#文件为Dummy class，211/211个生成shader为DummyShaderTextExporter。`arena_fidelity_assets.audit_unity_export()`可复核占位清单；即使没有这些占位，也不会自动判定为训练环境可用。

原始231个Shader二进制仍完整保留；UnityPy对Spine/Skeleton的文本导出不含实际GPU程序源码，不能拿空声明当作可重编译着色器。后续已从运行时元数据/原生库定位部分行为，并恢复4813份Lua源码；详见下文。NCONFIG底层diskdata仍待解析。

匹配编辑器安装于`/home/linn/Unity/Hub/Editor/2022.3.62f2c1/Editor/Unity`，版本输出通过；batchmode因缺有效许可证失败。Hub入口为`debug/arena-client/recovery-tools/unity-hub/app/AppRun`，许可激活需要用户自己完成账号登录及条款确认。运行时元数据/方法与碰撞分支的进一步证据见 [调查记录](../../.mr3a-records/archived/2026-11-08-arena-runtime-code-investigation.md)。未以占位脚本填补真实逻辑来制造可运行验收。

## Lua源码恢复

`LuaManager.CustomLoaderMethod`原生调用顺序确认：TextAsset.bytes → Util.DecryptBytesFromBytesAes(Key,IV) → CommonUtil.Decompress。只读核对运行时LuaManager的Key/IV字段均为Byte[]，分别32/16字节；材料保存在本地私有忽略文件，不打印、不入库。不要复用早先未经验证的lua-aes-key/lua-key-candidate猜测文件。

```bash
debug/arena-client/toolenv/bin/python tools/arena_lua.py \
  --input-dir debug/arena-client/export/84218715a6c56ab1c410ee5b9b4ec6dd.ab \
  --key-file debug/arena-client/raw/lua-runtime-key \
  --iv-file debug/arena-client/raw/lua-runtime-iv \
  --output debug/arena-client/lua-recovered
```

本次4813份、47929363字节源码全部通过AES-CBC/PKCS7、GZip CRC和UTF-8验证，0失败。工具限制解压大小，拒绝覆盖不同原件；recovery.json记录密文/明文摘要，任一文件失败非零退出。不执行Lua。源码包括热更、技能、敌人、配置调用和diskdata代理；存在源码不代表对应逻辑已移植/运行。NCONFIG文件由原生diskdata模块读取，尚未据此声明配置数据库已恢复。

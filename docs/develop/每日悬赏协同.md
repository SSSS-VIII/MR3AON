# 每日悬赏拉小号

在大号「每日悬赏」里开启「拉小号模式」，只需填写「小号配置」的「实例名称」。默认关闭。两号须已互为好友，小号须在自己的命名环境安装游戏、登录账号，并保存自己的「启动游戏」渠道/区服配置。

本次临时启用示例（不会修改保存的任务计划）

```bash
./run main --once --task 每日悬赏 \
  --task-options '{"每日悬赏":{"拉小号模式":true,"小号配置":{"实例名称":"xiaoli"}}}'
```

不加 `--once` 则继续沿用原调度。大号已有每日悬赏完成记录时仍会跳过，不会为了拉小号清除记录。需要长期启用时使用 `./run main --configure` 保存以上选项。不要把小号协同任务手工加入日常计划。

## 行为

- 大号进入任务时在后台准备指定小号。复用同一程序与源码，小号读取自己的启动配置，从主页现场识别当前昵称并传给大号，不需要配置UID或昵称。小号取消游戏内组队邀请屏蔽，并在主页等待；退出不重新勾选该游戏设置。
- 就绪后，大号在好友邀请列表匹配小号现场昵称，点击前原生联合识别同一行昵称和邀请按钮，直接邀请，不打开好友个人资料。好友备注、昵称截断或识别不确定会回退。小号只接受本次授权窗口内、正确邀请人发出的每日悬赏邀请，自动准备、参与战斗、处理结算并回主页等待下一场。
- 大号保留角色策略、Boss等待与首轮开大延迟；首轮开大后进入原生 `bossfight` 循环，持续点击武器、三个小技能和大招，后续大招可用时继续尝试释放。此覆盖只作用于每日悬赏，小号战斗策略保持原样。
- 小号不按自身奖励次数或参战场数结束；即使自己的奖励次数耗尽，仍结算回主页、接受下一次授权邀请并准备占位。正常结束条件由大号剩余任务决定，原有异常时限和父任务结束回收仍有效。
- 大号悬赏次数耗尽后独立打开每日任务页，循环领取所有可领取奖励并确认，再回主页登记完成；关闭好友/家族补打不会跳过领奖。
- 协同时始终固定小号组队，按大号剩余每日悬赏奖励次数结束，不再独立补打族员/好友龙血组队轮次。原龙血开关和时限保存在大号配置中；发生回退时按原值恢复。
- 小号的运行日志和协同调试日志都在该实例目录，新协同流水线不再保存奖励/结算截图；大号原有每日悬赏截图仍按原规则执行。大号任务结束、恢复重排、失败、q退出或中断时回收本次小号的CLI、Agent和Android后台，保留账号与数据。大号环境保留。

## 回退与时间边界

小号打开设置后先确认页面标题，滑动也必须处于设置页。未进入设置或用尽查找次数时，沿原生返回流程回主页后最多重开两次；仍失败再回收并回退普通组队，避免一次页面异常直接丢失本轮协同。

实例名相同、配置缺失、无小号自己的启动配置、已有控制者、启动失败、昵称识别失败、找不到好友或接受准备超时，均记录原因并回到原组队流程；不会抢占别人的控制权。除首次启动超时允许一次回收后重试外，本次顶层任务失败后不反复冷启动小号。恢复重排进入新的顶层任务时可以重新尝试，旧环境尚未回收则由同名互斥拒绝。

旧保存配置中的「游戏ID」字段会在读取时忽略，无需手动清理；新的命令行参数不要再传该字段。

准备与大号导航并行，首次准备最多两轮、每轮150秒，首次启动超时会完整回收后重试一次，大号等待上限360秒（含清理余量），后续轮次最多等待小号返回主页30秒；搜索好友最多30秒/6页；一次邀请等待加入并准备最多25秒。小号自身寿命最多30分钟，组队/返回异常120秒无进展会失败，战斗上限480秒。超时均回收环境，不依靠关闭窗口。

主Agent与小号worker通过私有生命周期管道关联，主进程异常消失也会触发回收。worker从启动到关闭始终持有小号租约，不能在CLI退出到关闭Android之间被新控制者插入。

`--once` 保留原退出码约定。仅对存在协同worker的调用，在CLI退出后额外等待最多45秒核对回收凭据，`MR3A_RESULT` 包含 `companion_cleanup_complete` 和 `companion_count`。小号业务失败但成功回退、回收，不会把正常大号任务误报失败；回收无法确认则返回1。外部中断仍返回130/143，同时返回回收结果。

## 接口边界

- `runtime.companion.CompanionManager` 管理启动、限时邀请许可、状态与回收；worker内部复用 `InstanceSession` 和 `launcher.prepare_command`。
- `PrepareBountyCompanion` / `CaptureBountyLeader` / `BindBountyFriendRow` 等仅桥接实例生命周期、原生OCR结果和动态昵称/同行ROI；邀请许可和准备回执使用本轮token。
- 新任务「每日悬赏小号」负责读取昵称、邀请设置与主页/组队/战斗/结算状态流转。它要求父任务创建的协同会话，独立误调用会失败退出，不自行挑选大号或无限等待。
- 界面识别、点击、滑动、轮询和场景分支全部位于 `每日悬赏.json` / `每日悬赏小号.json` 原生流水线；Python桥接不再直接截图、识别或输入。后台监督线程只管理进程和状态文件，不跨线程请求Maa接口。

## 准备失败截图

小号接受邀请后进入队伍等待，若5秒仍未确认准备完成，原生节点「悬赏小号准备未完成截图」保存一次当时完整识别帧，再继续原准备流程。每轮邀请重新计时，不循环刷图，不改变大号25秒等待与小号120秒组队期限；保存失败也继续原流程。复用 `LoopDeadlineExpired` 的截图和最多50张保留机制，不额外请求设备截图。

图片位于小号自己的 `debug/loop_deadline_expired/`，文件名包含「悬赏小号准备未完成」；xiaoli对应 `.mr3a-instances/xiaoli/debug/loop_deadline_expired/`。它提前于父任务回收，方便保留准备无效时可能存在的弹窗。新worker下次启动即加载。该诊断分支已有离线计时、完整帧保存、重复命中去重及保存失败继续流程验证，尚未实机触发。

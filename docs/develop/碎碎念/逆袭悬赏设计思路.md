# 需求
## 每日任务
1. 刷ABCD悬赏刷出逆袭A  
2. 清理自己的逆袭A  
3. 清理自己的每日逆袭次数  

## 每周任务
1. 刷逆袭A刷出每周逆袭S  
2. 刷逆袭S清理自己的每日逆袭次数  
3. 刷逆袭S刷出本期逆袭SS+  

# 实现难点
1. 进入队伍后被立刻踢，筛选选项会重置，此时来不及截图，无法用是否进入队伍判断按钮是否被重置，如果持续识别按钮状态会影响效率  、
2. 经观测，能够出现在玩家页面的ns悬赏为同时刻其他玩家点击发送并且点击进入人数不多的，所以必须在刷新之后立刻进入。
3. 点击准备时会被踢会点到"我的逆袭悬赏"（疑似，暂定）

# 设计思路
1. 抢悬赏模块开启前进行筛选  
2. 进入队伍识别到准备后识别悬赏是否为上层设定的值，分为四条类，未识别，na,ns,nss+，匹配则点击准备，不匹配则再识别一次后调用back返回主页确保流程稳定  
3. 点击刷新后立刻点击目标悬赏位置，不经过识别，提高效率，因为有检查模块兜底， 可以确保可用性，之后再进行识别悬赏点击进入的流程，并且识别到悬赏后可以进行连击，此刻并不违反识别再点击的的设计逻辑  
4. 战斗结束后进入检查模块，检查需要的选项，并动态修改筛选模块的节点，以及进入队伍后的检查悬赏模块的节点，如果均完成则任务结束  
5. 流程，先进任务检查模块，再进筛选模块，筛选模块后进抢悬赏模块，最后进悬赏检查模块，如果进入战斗模块，战斗模块后继进入悬赏检查模块，如果悬赏检查模块匹配失败，则重新进入筛选模块  
6. 为提高效率部分节点点击位置可硬编码，并将ocr替换为识图

# 情报模拟战

任务注册在「限时活动」，加入「日常任务」预设并排在3v3前；限时活动预设仍保持显式关闭，避免额外启用整组活动。main保存队列同样排在3v3前。沿用命名实例，也可临时运行：

```bash
./tools/run-intelligence              # main，本次只运行情报模拟战
./tools/run-intelligence xiaoli       # 指定实例，复用该实例保存的任务选项
./run main --once --task 情报模拟战
```

北京时间10:00≤当前时间<14:00、18:00≤当前时间<22:00开放；其它时间挂起到下一10:00/18:00，单次模式返回deferred/3。对局结束先确认结算并检查每日奖励，再判断是否继续匹配。每日任务是活动任务面板上方固定两条，分别确认「已领取」，不包含下方成就；完成后回主页，持久化禁用到次日05:00。

任务选项「无限打」（内部名`情报模拟战无限打`）默认关闭；开启后仍先领取每日奖励，两条全领取后关闭面板、重新检查活动时间并继续匹配，不登记今日完成。main目前已保存为开启，下次启动加载；其它实例未更改。它只取消每日完成出口，仍保留活动时段、任务1小时/单局15分钟超时保护；单次模式也不会因每日全领取返回完成。需要正常完成退出时把该选项关闭。

界面导航、教程、识别、点击、刷新、准备和领奖均在`assets/resource/pipeline/情报模拟战.json`。每回合只做两轮选牌，第一轮之后刷新一次，第二轮之后准备。五回合通过编号与原生max_hit去重，每局重置；倒计时短暂消失不会重新开始同一回合。重启测试时可从已确认的对局页面接回等待，不需要退出对局。

每手由原生批量OCR读取完整卡名、金币、剩余刷新次数和对手血量，消费空位识别结果；Agent调用`agent/intelligence_strategy`共用策略，枚举本手所有买得起的组合及合法空格落位，按当前棋盘累计至第五回合伤害＋被动/空位潜力＋分阶段留金币价值统一比较。不抽样后续发牌，不先截取6组，也没有随机续局推演。可在当前回合击杀时始终优先击杀，不为第五回合账面收益拖延。未知卡名不猜变体，剩余未知商店槽仍计入刷新机会。翻牌期间等名称带恢复，刷新后不会无限重试刷新。

五虎、洛青、银枭/雷龙等未触发阈值按计数参考表估值：根据余池匹配份数、当前进度、空位、金币及可见牌位，估计各剩余回合补齐的参考概率，再乘对应效果增伤。允许一手补多张，并计入本轮剩余刷新槽；不再用“差几张就等几回合”的硬截止。参考表采用匹配牌平均费用、未来每轮基础3金币与5张首手牌，未购买牌归池，匹配实物不重复收集；未模拟具体未来买牌/站位，概率并非真实胜率。旧运行Agent无新上下文时按本轮无额外刷新估计，重启加载后完整使用当前刷新信息。

产币效果未来估值恢复，按income_weight折扣，当前默认0.2（两成）；强制0≤权重<1，拒绝放大到1或以上。御守原折算42分只加8.4分，不再加84分；仍限制有效消费容量，不计第五回合结束产币。实际到账金币正常作为余额使用。校准过程与独立验证见[产币折扣](../records/archived/2026-11-15-intelligence-income-discount.md)。

取消提前占位扣分后，按独立回归校准金币价值：第1～5回合刷新前为12/9.6/7.2/4.8/2.4，刷新后为8/6/4/2/0；空位buff潜力权重仍为1，没有新增占位惩罚。校准过程与未达目标见[金币重标定](../records/archived/2026-11-15-intelligence-gold-no-slot-recalibration.md)。

点击、放置、刷新、准备与结算仍是原生JSON节点，Python不截图、不OCR、不直接控制设备。点击队列结束再读原生回执：金币扣除、目标格非空、原商店槽消失三者对应后才登记卡牌；失败点击不虚构战力。每实例`data/intelligence-battle-state.json`保存本局已确认棋盘和待确认动作。正常规划日志mode为scored；未知旧局/状态矛盾降级为受金币和已识别空格约束的保守选择，下一新局恢复正常。血量未知的后期回合优先当前伤害；金币未知不盲买。

匹配前只预热本手组合/落位枚举的C++17核，正常选牌不承担首次编译耗时；本机使用g++，编译不可用会明确记录降级。`tools/intelligence_simulator`只是共用策略的兼容导入入口，不复制实现。正在运行的Agent不会热加载Python修改，下次启动使用新版本。

结算用「当前积分＋剩余血量＋确定」定位；每回合的临时战斗结算没有当前积分，不会误点。整个任务上限1小时、单局15分钟；无法确认完成或超时走失败恢复，不写完成状态。总超时交给已有 `RestartGame` 和 Agent 调度启动游戏后恢复当前任务，不能直接 `AbortTasker` 停掉整队。

## 游戏重启更新与维护后的恢复

2026-11-19 10:00–11:00，维护中的活动入口仍可被OCR识别，导航反复点卡片，普通30秒节点超时因此不会触发；原总超时直接AbortTasker，导致11:00结束整个队列。12:38只读截图又确认出现「游戏有更新／重启客户端」弹窗，旧启动流程仅处理「确认更新」，两处问题共同阻断后续恢复。

现在导航与通用错误/返回恢复优先联合识别更新标题和重启按钮，业务任务走已有重启调度边界：停止本账号游戏→启动游戏→恢复原任务及选项。启动任务内遇到同一弹窗，先解除闪退监视，再原生点击「重启客户端」，经既有启动应用与监视流程继续更新；不将主动退出当成闪退，也不在启动任务内调用业务重排。更新弹窗没有被确认时不盲点。

真实更新弹窗原生OCR正例、缺标题/按钮负例，以及恢复边界与情报模拟战回归共43项通过；资源整包随回放加载通过。未实机点击更新、重启实例或重开队列，当前已退出的脚本需重新执行 `./run` 加载修复；真实下载/登录后恢复仍待验证。

# 命名实例与后续控制接口

MR3A 以名字标识环境。`./run` 等价于 `./run main`，保留现有主账号配置和 Android；`./run 小号` 使用持久独立环境。调用者不选择 Waydroid slot、ADB server 或设备地址。

`./run 名字 --no-window` 只启动后台，不打开桌面窗口；`--check --no-window` 可只准备和检查设备。launcher 将本次窗口策略传入子进程，`InstanceSession.ensure_ready()` 及故障恢复沿用它；每次进入 launcher 都明确重设策略，不让其它普通启动继承后台模式。小鲤包装入口默认加此参数，其他实例的普通启动保持原行为。

## 共享与隔离

所有名字共用 MaaPiCli、动态库、Agent 源码、虚拟环境、流水线、模型和图片。main 继续使用 `deps/bin/`，其它名字使用 `.mr3a-instances/<名字>/` 保存运行数据。每个环境独立保存 PiCli 配置（包括登录选项）、任务状态、框架/Agent 日志、奖励图、超时截图、元数据缓存和学题数据。

新名字从空任务配置开始，不克隆主账号密码、账号输入或每日禁用状态。Android 用户数据同样独立；游戏安装和账号登录需在该 Android 内完成。同名再次启动不会重建或覆盖配置。

旧奖励迁移已经完成，迁移机制及残留已移除。新日志和奖励统一写入实例目录，启动不再导入旧奖励。

## 设备层边界

`agent/runtime/instances.py` 提供名字注册表与 `InstanceSession`，负责生命周期、目标解析、连接、恢复和截图。它不会修改调用进程的全局 ADB 环境，多个句柄可以在同一进程中分别访问不同名字。

```python
from runtime import InstanceSession

session = InstanceSession("小号")
session.ensure_ready()
png = session.screenshot()  # PNG bytes，调用者不处理 ADB 或 IP

with session.control():
    session.tap(200, 620)
```

`control()` 是跨进程排他租约。脚本由 launcher 持有租约并跨 exec 传给同一份 MaaPiCli；输入控制者必须取得同一个租约，不能与正在跑脚本的同名环境争抢操作。截图和状态读取可独立进行。未来服务可以在此层之上处理帧编号、请求排队和业务动作，底层传输也可替换而不让调用者接管端口。

现有 Agent 的 Waydroid 检查、重启和 ADB 操作从名字绑定；目标不在线时失败，不会退回另一个可用设备。TUI 退出只结束当前实例绑定的 PiCli；孤儿回收也按运行目录隔离，不再对其它实例做全局进程/Socket 清理。

## MFA 发布兼容边界

当前命名实例封装服务于本机 Waydroid + 定制 MaaPiCli，仍使用标准 Adb 控制器和共享 Pipeline/Agent，没有替换 MaaFramework 的控制器或 Tasker。它补充的是 Android 生命周期、名字绑定、运行目录和外部输入互斥，不能等同于已适配 MFA 的多实例发布。

未来 MFA 入口应由 MFA 管理实例配置、模拟器启动和控制器，Agent 接收对应实例身份与当前控制器信息；不要同时让本地 launcher 和 MFA 管理同一设备的启动/恢复。MFA 上游已提供实例标签页及按实例保存的启动程序/参数，Agent 启动也传递 `MFA_INSTANCE_ID`、`MFA_INSTANCE_NAME`，发布适配时须核对实际打包版本。

发布前仍须接通三处：自定义 ADB 操作绑定 MFA 当前控制器而不是发现到的唯一设备；按 MFA 稳定实例 ID 隔离任务状态、日志、奖励和缓存；将 Waydroid 重启恢复限定在 Waydroid 后端，并把控制租约及停止行为接入 MFA 生命周期。当前 `MR3A_*` 路径与设备绑定由本地 launcher 注入，直接运行 MFA 不会自动获得这些隔离保证。

验收应包括同一安装目录的两个 MFA 实例并行运行、重启后身份和状态复用、各自截图/输入/恢复不串设备、文件不串目录、停止一个实例不影响另一个。目前未进行该验收，不宣称现成 release 已支持多实例。

## 后续范围

显式接管使用 `with session.control(takeover=True, timeout=10): ...`。普通 control 仍然遇占用即拒绝，不自动停止别人。接管通过 `/proc/locks` 核对本实例锁 inode 的真实持有进程，再用 pidfd 固定身份并复核锁归属；不删除锁文件，也不接受外部 PID。MaaPiCli 先发 SIGUSR1 请求正常停任务，其它控制脚本先 SIGTERM，限时后才结束残留进程及已核验的子进程。如果进程树还持有其它实例的控制锁，拒绝停止；如果新请求抢先接过锁，本次请求报错而不连续终止新的控制者。

小鲤受限工具暴露 `game_control {"action":"takeover"}`，固定使用 xiaoli，不提供实例名、进程或端口参数。Android 和账号保留，不自动启动设备。操作结束仍释放单次租约，后续再截图和输入；不会形成跨多步业务的长期占用。

显式关闭使用 `session.shutdown()`（命令为 `./run 名字 --stop`），它取得控制租约后停止 Android 会话和容器管理后台，保留磁盘数据。与之不同，恢复用的 `stop()` / `restart()` 保留管理服务以减少恢复开销。同名脚本运行期间拒绝关闭，调用者先退出脚本；读取截图不需要控制租约。

这层是大小号协同与 dsh 的基础，不是智能体服务本身。本次没有实现 agent HTTP/MCP 接口、观察/动作协议或邀请、组队等大小号业务。

未来封装应复用名字注册表和 `InstanceSession`，不另建一套实例编号、端口分配、截图命令或账号配置。需要实际输入的 dsh 会话应持有 `control()`；与脚本共享观察可以只调用截图/状态方法。

CLI 用法和验证命令统一维护在 `.mr3a-records/test-environment.md`；该文件的旧测试目录约定已被命名入口替代。
## 外部游戏能力与任务交接

小鲤独立插件位于 `~/xiaoli/game/`，工具名为 `game_control`。`~/xiaoli/run` 只调用本项目 `run xiaoli --task 启动游戏`，使用小鲤自己配置中的渠道和区服。MR3A 准备环境并独占执行启动任务，完成后退出脚本，保留 Android 给小鲤。当前配置为 OPPO、上次登录；未提供账号，实机只验证到 OPPO 账号登录页。

设备操作通过 `~/xiaoli/game/control`，每条请求在 `InstanceSession.control()` 内执行，再立即释放；不再有常驻服务占用租约。设备未运行或连接离线时，调用启动入口，由原 run 统一恢复，不在外部管理端口或复制生命周期。status 可在脚本运行期间查询是否忙碌，输入请求会拒绝与 MR3A 同名脚本并发。

公共 `adb(*args, timeout=..., input_data=bytes)` 返回含 bytes stdout/stderr 和 returncode 的 `subprocess.CompletedProcess`，不会自动重试失败动作。它不允许切换 serial、服务器、连接或端口；宿主 push/pull/install 文件目录由上层校验。见 [本次纠正与验证](../../.mr3a-records/archived/2026-11-01-xiaoli-startup-task-handoff.md)。

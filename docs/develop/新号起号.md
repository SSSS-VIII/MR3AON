# 新号起号（v1.6.2资源接入）

从已创号成功的新手剧情推进至中忍；不负责注册、短信验证或渠道登录。当前仅完成代码及离线验证，尚未使用实际新号验收。上游推荐九游；其它渠道需另行验证。

## 使用方式

使用独立命名实例，不在已有 main/xiaoli 账号上尝试教程。游戏安装、渠道登录和创号由使用者先完成。实例仍共用现有程序和源码，框架保留5.14.2。

```bash
./run 新号 --configure
# 选择“新号起号”预设，并为各阶段填写相同的非敏感账号标识
./run 新号
# 只执行某一阶段；沿用保存的该任务选项，不改变计划
./run 新号 --task 起号05
```

起号01应在创号后的动画至「六个月前，忍之谷」之间启动；02～14按任务说明图对应页面启动。预设中必读加14段按序排列，不要与日常/其它工作流混在同一计划；未选择的段不会自动加入。起号任务的账号标识必填，是本地进度分组用的代号，不是密码，也不会自动核验游戏内账号。每次换号须修改标识。

## 进度和中断

进度保存在所选实例的 `config/staged_workflows.json`，按工作流、账号标识和流程版本隔离，不随每日05:00重置。成功识别本段结束页面后才登记完成；以后同作用域再次执行会跳过已完成段。

运行中崩溃、识别失败或未经过成功登记就结束，会停止该起号计划，保留 running/paused 状态；不会自动重启游戏并重放剧情，也不会跳到下一阶段。公共返回链出错也走相同策略。

中断后先人工检查当前页面及召唤、强化、升级等已经执行的步骤。可以把游戏恢复到某段起点，再只运行该段。若该段留下了未完成记录，须在该任务配置里开启“起号手动确认重试”；这会重新执行该段入口，不能在未知的中间页面盲目重试。使用后将此开关恢复关闭。已完成段不受该开关影响，仍会跳过。

当前检查点粒度为阶段，不会自动从阶段中间的某次召唤/强化恢复，也不会根据“第三关”“第九关”等重复出现的标签自动推断进度。代码明确阻止未确认的自动重放，但人工确认重试仍可能重复消费，应先核对现场。

## 动作时序

默认“上游等待”维持原始动作语义：每次输入完成后再等待指定毫秒数，不添加3v3的固定+60ms。可选“绝对时间轴”会扣除输入耗时，必须逐关验证后再使用。

首段等待0～10000ms只在每次关卡动作序列开始前应用一次；间隔偏移-500～500ms应用于各点击后的间隔，默认均为0。它们按本次任务配置传入，互不修改其它实例、关卡或3v3动作。长等待仍可被停止请求打断。

## 开发边界

- 原始361节点和10段点击数据取自上游固定v1.6.2，关卡动作仅替换时序绑定器。
- 各段entry增加BeginWorkflowStage，原结束识别后接CompleteWorkflowStage及StopTask；没有成功登记时不得通过调度兜底继续。
- 专用失败节点PauseWorkflowStage停止队列，不复用日常恢复。默认错误和公共back错误在当前任务context内重定向，不全局改写资源。
- 阶段状态写入采用临时文件、fsync和原子替换；坏文件和不同版本进度拒绝静默覆盖。控制租约仍由run管理，不新增ADB/设备生命周期管理。
- 本轮按用户要求不实跑；新号01～04闭环、剩余阶段、错误页面、动作偏移及不同渠道均属后续实机验收项目。

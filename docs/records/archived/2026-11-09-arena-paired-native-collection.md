# 原版步进配对标注与原生数组兼容

## 现象与需求

用户已明确允许微调现成 YOLO，不自写网络。为覆盖小黑绳下、换边和两段跳姿态，需要通过原版输入收集图像/碰撞框配对样本，并保留独立回合验收。

## 原因

此前逐帧多次 RPC 轮询既慢又没有必要。原版 Lua 的 `json.stringify` 会把部分一基数组写为 `{"1":...,"2":...}`，而桥接 RPC 返回标准数组，两者混用使直接读取新标注失败。敌人对象池还会复用 InstanceID，不能拿同一个 ID 跨消失/重生比较未来轨迹。蜘蛛长丝线和隐藏机关的 Renderer 也不能代替可见本体。

## 改动

- `paired_collection.lua` 沿用原 `advance`，结束后等待一次原相机更新，暂停物理并写入带唯一请求 ID 的标注；宿主取图后才继续下一步。
- 收集器复用 arena 的 InstanceSession/FastCapture 租约，增加仅开发命令行的原生随机跳跃/下翻采样。中断时有界等待已有步进完成，再恢复暂停菜单。
- 标签本体采用原 `_allRenderObj`，排除粒子和透明隐藏 Sprite，保留 collider 原字段。
- 读取时递归兼容连续一基数字键数组，空表、稀疏数字映射不擅自改型，原始证据不改写。
- 轨迹验收遇原 ID 中途缺失、资源变化或明显瞬移，拒绝跨池复用配对。这个检查不是全生命周期编号，不能保证辨出同位置无间隔复用。

## 验证

arena 实际完成 test44 626 帧、explore45 627 帧、curve46 227 帧、test49 626 帧、curve48-highrate 701 帧的暂停原画面配对采集。explore45 包含绳下 295 帧、绳上 207 帧、下翻 33 帧、上翻 22 帧及跳跃/下落姿态。高频回合原物理步长 1 tick，14 秒共 701 帧。均恢复原暂停菜单；无 main 输入。

在独立 YOLO Python 3.12 环境执行 native_labels、visual_data、vision、motion 共 32 项测试通过。项目基础 `.venv` 缺 cv2，那里相应测试会跳过，不能用跳过结果替代以上完整执行。微调与实时控制结果另记，采集完成不代表跑图验收通过。

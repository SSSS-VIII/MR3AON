# 小鲤启动游戏不勾选屏蔽组队邀请

## 需求

用户要求调整小鲤的启动游戏任务，不再勾选屏蔽组队邀请，主环境继续原有行为。

## 原因

原启动流程确认主页后会使能「启动游戏点击主页设置」，进入设置识别邀请屏蔽项，再勾选屏蔽。资源由实例共享，直接修改公共节点默认行为会同时影响主环境；仅把设置点击节点 enabled=false 也会被后续 EnableNode 再次开启。

## 改动

- 启动游戏增加选项「启动时屏蔽组队邀请」，默认「是」，不提供覆盖，保持其它环境已有行为。
- 「否」覆盖「两次识别成功后则确定进入了主页面」为 DoNothing 后直接进入「启动游戏到了主页面」，跳过使能和打开设置页。若启动时已经在设置页，「屏蔽所有组队邀请」只进入收起设置链，不再经过勾选节点。
- 语义为保持游戏原有邀请设置，不主动取消已经勾选的屏蔽项；选项说明明确该边界。
- 小鲤实际配置的唯一启动任务和无凭据模板均显式选择「否」，保留任务计划、OPPO 渠道、区服和账号输入。main 实际配置不改。
- 小鲤仓库提交 `589ea28` 只包含本次模板和独立说明 game/startup-invites.md，不包含其正在开发的 run、控制器、插件及对应测试改动。

## 验证 / 边界

- 5 项启动/渠道保护测试、10 个子测试通过，新增覆盖验证默认仍屏蔽、「否」跳过设置使能，以及已在设置页时的退出链不会触达勾选屏蔽节点、最终仍能 StopTask。
- 用真实 MaaFramework Resource 加载完整资源并执行 override_pipeline 成功，读回两个覆盖节点分别为 DoNothing→主页面停止、DoNothing→收起设置链；未连接设备或执行点击。
- 小鲤当前工作区控制器 13 项现有测试通过，其它并行工作不纳入本次提交。
- 实际配置已写入并读回核对；main 配置 SHA256 未变。另有设备操作进程持有 xiaoli 控制租约，本次没有发送 ADB 操作或中断该进程，只更新下次启动使用的磁盘配置；未实机重跑游戏，不能声称已取消游戏内原有勾选。

# 当前飞竹状态识别与危险预报链核对

## 用户问题与核对范围

核对当前v15实际profile、arena_bamboo_motion.py、arena_obb_detector.py、arena_vision.py、原监督映射和v13阶段归档/提交。仅只读源码与已有产物，不启动设备、训练或修改控制行为。用户已有暂存常驻任务保留。

## 当前实现

同一个标准YOLO有bamboo_aim/locked/attack三类。原标签映射none/aim→瞄准标记、aimLock/readyAttack→锁定标记、flyToNinja/insertEdge→攻击体；运行时只预测画面外观，不读原_enemyState。锁定与准备、飞行与插边未分别建视觉类。中部标记是cue，原实际启用的AimLine物理框另保留，不能说所有瞄准线都被从物理监督删除。

准星置信≥.25，同中心8px内先保留最强候选，再跨帧位置关联；总观测≥3、锁定观测≥2建立发射时钟。原锁定.5s+准备.5s，以观察到的瞄准→锁定边界估1秒后的发射窗，并留分类曝光滞后/离散时钟余量。若首次已锁定且没有近期瞄准，发射窗约为首见−.04到首见+1.04秒，而不是重新等待整1秒。锁定目标Y取最近3次相机补偿后准星高度中位数；已建立时钟不重置，锁定标记仍可更新目标高度。

危险输出为未来时刻的矩形包围范围：原长度3world/高度上界.2world，水平速度−60world/s加像素场景流；滚动未知按−80..−60world/s包住，原两种出生中心差保留X区间。时间、速度、出生点的不确定取范围。真实攻击体另一路YOLO/跟踪，右/左裁切恢复原长度，初始速度先验后用像素回归，保持相机参考系中水平直飞。MPC把这些范围与原跳跃/下翻轨迹及输入延迟后的状态比较。

## 已确认限制和未完成项

首次锁定晚见会很宽；未建时钟前标记失联约.25s会清，不能补出未见起点。8px空间去重及纯位置关联可能合并重叠标记，没有完整的多发射器身份/数量建模。预报轨迹与真实飞行轨迹在ObbPerception里直接extend并存，没有可靠的一对一接管/去重，也没有实测发射反校时钟。attack类同时包含插边，未显式分开停住状态。

这些是源码可确认的限制，不能直接断言是某次400伤害的原因；需对齐既有受伤回合的原图、准星类别、时钟窗、实体轨迹和动作收据再定位。原v13测试222/243提前.4s覆盖是旧特定范围口径，不代表当前所有飞竹准确率。此次无代码改动，未重跑测试或原生回合，默认v15及暂停环境保持原状。

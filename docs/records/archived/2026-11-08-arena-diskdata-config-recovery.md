# NCONFIG配置数据库恢复与竞技场资源映射

## 需求 / 原因

全面还原需要真实角色、敌人/物品预制体映射以及竞技场章节配置。Lua已恢复，但NCONFIG本体此前不能读取，不能仅凭旧Stage枚举猜资源或路线。

## 调查与改动

已恢复ddata.lua明确调用diskdata.init(fileName,1)。只读核验原进程与libxlua映射，取得库的运行时虚拟布局分析副本；必须按虚拟地址读取，不能用受保护ELF中重叠文件段覆盖后的结果误判无符号。按PT_DYNAMIC定位动态符号，找到luaopen_diskdata及init/get等注册函数。

init在文件尾读取uint32并XOR固定格式标记取得目录长度，再读取目录；原生0x9623c循环使用64字节材料独立解开每块。材料只在忽略目录私有文件，不打印、不提交。目录/记录为Lua序列化格式：低3位类型、高5位cookie，包含多种整数宽度、浮点、字符串、数组+映射混合表、共享空表引用。长度头、扩展数组和记录引用均需验证，不能用文本搜索或JSON猜测替代。

新增tools/arena_diskdata.py，纯离线解析，不执行Lua/本地库；保留数组、数值键和混合键，拒绝原生userdata、损坏边界和缺失目标表；写出每条记录原始位置/长度/明文摘要及源文件摘要，拒绝冲突覆盖，出错列明且非零退出。无--table时恢复全部表。

## 验证

当前动态NCONFIG源86636038字节，目录1830817字节，恢复2029张表、141067条记录，0错误；结果debug/arena-client/nconfig-all/recovery.json。所有块按原始包长度和边界解析，未凭乱码补造条目。合成测试验证数值宽度、混合键、截断、userdata拒绝、非法扩展数组、目录/行独立解码、缺失表及错误材料；与提取/Lua/恢复工具共29项通过。

交叉证据：CfgGameItemInfo[40]实际resourceName=ItemAirGround、editInfoScriptName=ItemInfoAirGround；CfgRoleInfo[1]为小黑；CfgEndlessData实际含章节levelDataList/nextLevelID链。已恢复CfgEndless/Gale/Reserved1与难度/随机条件，以及角色、物品、敌人配置，不能再说数据库仍未解开。

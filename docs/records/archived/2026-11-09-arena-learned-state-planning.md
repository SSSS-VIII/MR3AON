# 从已识别原生状态推进轨迹与滚动规划

## 原因与改动

八类模型的预备/冲刺识别通过后，直接沿旧决策仍受伤420。检查发现两处接口不一致：关联旧轨迹仍只用平均速度，没有使用已建立的运动模型；旧绳下逃脱还会在上翻后强制执行预先安排的跳跃，不重新检查新画面。

- `Tracker`关联预测改为同一`future()`模型，涵盖曲线、反弹、预备→冲刺，而非另用直线公式。回归构造起冲速度尚未被平均值捕获、旁边还有静止相似物的情形，确认原ID继续属于移动目标。
- 八类模型输出的状态仅来自YOLO类别。`Track`保留视觉预备起始时间，按原ready0.3秒、世界冲速-10/角色14、碰撞范围1.3倍/约0.06秒变大预测；原始测量速度不冒充该速度先验。外推同时推进预备剩余时间和缩放进度，满足分段推进与一次推进一致；缩放目标取预备起点，避免逐帧复合放大。
- 带有明确学得飞行状态的轨迹和弹球共同进入约0.96秒滚动搜索。只执行第一步，后续重新从图像决策；六类旧模型保留原路径，默认权重尚未切换。

未修改原游戏的时序、碰撞、伤害或敌人行为，没有将原生状态字段直接传给运行策略。

## 验证

- 163项arena回归通过、2个依赖缺失模块跳过；新目标关联、状态前推、碰撞增大、分类状态映射均有回归。
- 固定同一段网络输出回放，旧/新关联创建277/275个轨迹，相近轨迹对帧数139/131；这是诊断量，不等于原生ID正确率。
- `states-live48`旧决策累计420；`states-associated48`运动模型关联后240；`states-planning48`滚动规划后**三块连续无伤**，1101→11022→11032，到11042结束，minHealth/health均5000、god=false，31次输入均确认。截图→Unity按键P9563.50ms，源码/先验17个SHA与工作区一致。
- 复验`states-planning47`为360（0/120/240），`states-planning54`也为360。不能用seed48的一次无伤宣布随机全场景稳定。三轮原生渲染均约60FPS，规划本身P95约28–29ms、峰值40–45ms，仍占较多控制延迟。

当前继续优化规划计算开销与复验，八类模型仅用显式`--detector-weights`试跑，默认六类模型保留。原素材/权重/帧/日志在忽略目录，用户已暂存任务JSON不混入提交。

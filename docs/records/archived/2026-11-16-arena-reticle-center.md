# 飞竹孤立准星圆心的独立 CPU 模块

## 需求与原因

用户要求飞竹瞄准/锁定及重叠识别继续优化，不能把有伤结果写成无伤。此前离线审计发现，现有准星框中心与原 Sprite 中心有明显偏差；直接在 ROI 内选最强纹理峰又会吸附到邻近准星。本次把经过完整回放的保守精修整理为独立模块，先保留选择性定位收益，不与正在进行的时序或动作实验混合。

原资源核查并不支持统一平移观测：`point` 的 pivot 为 (.5,.5)，Sprite/Center/Aim 局部位置均为零，原 Sprite 旋转45°、scale .85、Aim scale1.1。2690 个锁定态配对中，Sprite 中心与同时刻 `_lastAttackPos` 投影 Y 的差值中位+.0896px、绝对P95 .2125px；现有规范化框中心与 Sprite 中心的差值中位+1.6412px、绝对P95 4.3417px。相机投影仍有少量差异，未把可见圆心和未来攻击中心视为绝对相同坐标。

## 改动

- 新增 `tools/arena_reticle_center.py`。`ReticleCenterRefiner.refine(bgr, boxes)` 只接640×360 uint8 BGR与按原顺序的检测框；每个输入都返回一个 `CenterResult`，包括 `proposal_index`、可选精修 `center`、拒绝 `reason` 和证据。接口不接原ID或phase，不改变原框、完整cue或图片。
- 使用时调用方保留 `cues`，仅将 `[cue['box'] for cue in cues]` 送入模块；阶段分类仍使用原框。拒绝时 `center=None`，不得据此删除原cue。模块未连接 `ObbDetector`、`BambooClocks` 或 runner，没有改变当前运行行为。
- 保持冻结原型：原红星纹理提出候选，红色圆环确认；多个≥.6确认峰、另有≥.5次峰或邻近原预测框均拒绝。白色像素只检查另一圆环以否决歧义，不创建接受中心，不推广白纹理匹配或重叠多目标版本。
- 局部复制已审查的顶部/底部圆形裁剪规范化，测试与现有 `reticle_tracking_box` 对照；不导入正在实验中的竹子时钟或动作模块。
- 原资源配置为 `arena/vision-reticle-center.json`。路径相对仓库根，不依赖运行时cwd；原PNG SHA256为 `2d4cc4ecbb71394fa7c8d1bc288621615709a013d3dc909d83c27b278dcf8ee5`，对应本机 `debug/arena-client/arena-entities/texture-previews/-1873529890869447913-point.png`。仅新增路径/摘要配置，不把客户端纹理或整包资产纳入Git。
- 初始化只读一次文件，先校验SHA再解码，检查原34×33 RGBA尺寸。缺失、不可读、SHA不符、无法解码或尺寸不符均有明确资产状态，后续每个输入返回相应拒绝；不下载或替代资源，不在逐帧路径读文件。配置版本/摘要格式错误直接报错。
- 近邻拒绝前置；每ROI至多10次模板匹配、6个候选、12次圆环检查，像素计算范围每边不超过69。相关峰先保存在NumPy数组，以稳定排序保持原顺序，避免平坦红色ROI为每个相关峰分配Python字典。`last_stats`记录CPU/wall毫秒、实际ROI/模板/圆环调用数量，不更改OpenCV全局线程设置。

## 定位结果与边界

先用每五帧抽样340帧固定保守门控，再对六完整回合1683帧复核；扩到同回合全部帧是时间范围扩展，不是独立测试。原ID、阶段及重叠标记仅在后验评分中使用，均没有进入裁区或接受逻辑。

- 六回合8649 proposal接受3793（43.85%），3717个原框IoU≥.5配对样本中心误差P95从5.072降为1.108px，Y绝对误差P95从4.247降为.915px；错吸附到其他真实准星为0。保留1个瞄准态3.093px尾差，没有按该样本调阈值。
- 真实锁定态接受776/2732（28.4%），中心P95 1.069px、最大2.235px；真实瞄准态接受2941/5363（54.8%）。408个近重叠目标只精修命中7个，多数主动拒绝，不能据这些数值宣称重叠已解决。
- 冻结后另外使用此前未用于圆心研究的sealed-v16两回合722帧，沿用旧main15缓存proposal而不重新推理：3027个接受1803，1778配对中心P95从4.488降为1.075px、最大1.390px，错吸附/无真实中心均0。真实锁定态接受376/1035（36.3%）。上游模型不同，这不是当前main21的闭环验收。
- 抽样中19个未进入原Y=55..360评分区的接受点，逐个核查均为评分区上方的真实准星，距原中心≤3px。六整回合76个框评分未配对点、独立两回合25个同类点也全部对应原中心≤3px，详细位置及每回合/phase接受率保留在研究JSON。

研究原型曾出现一次76.47ms CPU异常峰，同像素20次重放未复现；该初次结果仍保留，不无证据归为热身。高负荷13-proposal帧重放wall P95 16.60ms。上述定位结果未经过实际Tracker/时钟/危险窗口或原生连续控制，不代表无伤，尚未解决原观察缺失、重叠归属或相机参考误差。

# 工坊挑战改为原生流水线并领取全部可领奖励

## 现象与需求

用户指出首版把整段界面控制放进Python，要求改为项目惯用的JSON流水线；随后要求移除工坊截图、结束前领取全部可领奖励，并授权用xiaoli实机验证。main已有日常脚本控制，本次不接管main。

## 原因

首版 `RunWorkshopChallenge` 内自行截图、OCR、点击和循环，流水线只有一个入口，无法直接查看具体UI步骤。领奖逻辑只绑定四类非通关目标，导致已经达成的通关类奖励也被跳过。首版main实测只证明四类目标完成，不能表述为领取了任务页全部奖励。

## 改动

- 删除工坊专属Python控制器及注册。导航、首次说明、任务滚动、同一行目标/已领取配对、分享、三张地图轮换、战内挂机和结算全部写入 `工坊挑战.json`。
- 保留已有通用计数、时限、节点覆盖与Agent调度能力，不增加工坊专属自定义动作。四个目标逐项识别已领取，必须全部确认才正常完成；不主动完成通关目标。
- 每页先一键领取，再兜底逐项领取任意可领奖励，包含已完成的通关目标。领取后重新扫描任务页，确保领奖后才结束。
- 移除任务的奖励和结算截图。框架原有异常诊断截图策略保持原样。按用户要求清理首版生成的main工坊奖励截图17张及空目录，其它任务图片保留；奖励分类枚举忽略已不存在的目录，不改在用主脚本的注册表。
- 保留周六/周日执行、周六09:00前挂起、结束/非周末持久禁用至下周六05:00。保留单局8分钟、总计1小时、最多18局边界，耗尽按失败退出，不能写成完成。
- xiaoli首轮发现新用户说明页和主页入口OCR遗漏：增加说明页原生联合识别和主页图标模板兜底，并增加截图回放验证。

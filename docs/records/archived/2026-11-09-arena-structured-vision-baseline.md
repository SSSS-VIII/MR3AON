# 结构化视觉第一版与连续板实测

## 需求

用户确认按人物状态、陷阱位置/差分速度/运动轨迹的结构化路线实现第一版，在隔离原客户端里自动实验到能跑过几个板子。本次不再只给方案，也未训练整图循环策略。

## 改动

- `arena_vision.py`做640px前处理、人物/绳地状态、眼部与球体等特征检出、对象关联、遮挡保留及速度/加速度/周期拟合。单帧截图不负责独自推断完整状态。
- `arena_terrain.py`测近处支撑和断口；`arena_policy.py`用原采样动作/碰撞箱先验比较约0.76秒候选轨迹。没有板子ID或操作时间表输入。
- `arena_visual_runner.py`连接原生选关、高速捕获、原键盘；独立线程记录原图和验收，画面重复不重复喂给速度回归。记录原帧、估计、提议/实际动作、观测年龄及客户端按键接收时间。
- `vision_eval.lua`只做验收，逐渲染帧累计掉血、记录最低血量和K/S接收，另记原板子位置。策略不接收内部角色/敌人坐标或状态。进入目标位置后有伤结果明确标为passed_with_damage。
- `vision_labels.lua`和`arena_snapshot_labels.py`提供暂停画面及真实collider标注，供验证/之后训练；不是部署输入。`run-arena-vision`复用本地依赖路径，结束恢复原暂停菜单，没有新增游戏菜单项。
- 原动作先验、短按漏键及长RPC拖慢渲染问题已独立提交/归档，不混成一个“整理工作区”。原APK、陷阱物理和其它实例未改。

暂停原标注工具实机生成角色和4个原对象标签；其中2只在可见范围的蜘蛛均检出，中心误差约0.55/2.87px，人物估计中心与原Role中心约1px。小眼睛因分成两个21像素组件曾漏检，已通过局部闭合合并；深色背景下不再用缺少背景反差直接否定眼部。该检查不是全量检测精度验收。

原动作完整CLI重测成功；校准结果另见[运动先验](2026-11-09-arena-native-motion-priors.md)。早期run19错误标记已作废，后改为重建采样协程并同时核对当前HP/最低HP/逐帧累计损伤；对应回归防止旧minimum字段掩盖受伤。

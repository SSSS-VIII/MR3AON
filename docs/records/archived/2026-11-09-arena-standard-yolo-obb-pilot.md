# 标准YOLO OBB原资源与物理形状试验

## 需求与依据

八类粗分不能区别资源/物理形状，旋转机关和斜支撑也不宜丢掉角度。新增标签配置以当前疾风69类型的原资源/Prefab Collider为来源，物理形状、原直线飞行阶段和绳/地面/浮台、无激活伤害体的可见cue分开。共有159个类别声明，不能理解为159类训练完成。

使用官方[YOLO OBB格式](https://docs.ultralytics.com/datasets/obb/)与[标准OBB模型/训练接口](https://docs.ultralytics.com/tasks/obb/)，没有自写网络、Trainer或loss。角色和Sphere/Capsule保留平面范围，Box用实际旋转四角；旧schema4无非Box平面四角时复用已校核的投影反算。Collider按最近EnemyBase归属及原Enemy tag取物理目标，层信息保留：水果的伤害Collider在layer17，初版只选layer9会错误丢掉，已修正；data-obb-probe仅诊断，不用于训练。

## 工具

arena_yolo_obb_data.py生成原生整回合数据、profile.json与来源摘要；同路径/同地图种子的回合禁止跨训练验证。完整支撑要求schema4，不能把旧未标浮台/绳的图当作负样本混入。原静态配置及训练观察到的资源名/脚本名保存到profile，缺Cfg的原始ID保留type_N，不编造资源绑定。

arena_yolo_obb_score.py分别报告严格类别/阶段、同资源、纯空间多边形匹配和各支撑类别，避免拿找到大致危险物代替认对阶段。arena_yolo_finetune.py仍调用标准Trainer，增加可选transfer加载已有游戏兼容参数，后续新训练自动保存对应profile和来源摘要。旧六/八类训练调用不变。

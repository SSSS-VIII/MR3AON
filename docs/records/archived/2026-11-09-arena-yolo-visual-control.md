# 微调 YOLO 接入原客户端视觉避障闭环

## 需求

继续实现用户已授权的高速截图→陷阱/人物识别→差分速度与轨迹→原输入决策，在本地原客户端实际跑若干板子。用户已允许微调现成 YOLO，不允许自写网络；本轮模型适配见[独立训练记录](2026-11-09-arena-standard-yolo-finetune.md)。

## 原因与改动

- 新 `YoloDetector/YoloPerception` 使用官方YOLO26n六类碰撞标注权重，预热后再恢复游戏。简单线段/地面检测仍负责支撑几何，没有重新接入手写敌人候选。角色框以本帧检测为准，原动作先验不能覆盖测量；最多220ms短时漏检预测。跨帧横向关联允许原生拖拽角色离开旧100–330px ROI，同时排除远处相似物。
- 原标注投影三维AABB的八个角，偏离屏幕中心时会膨胀，不能直接视作二维球体/胶囊。测得原Camera.main焦距434.558px、角色深度11、FOV45，平面尺度39.505px/世界单位，写入 `vision-camera.json`。`arena_projection.py`反解球体和竖直角色胶囊；已核对参考图中属于蜘蛛/飞行/弹球组的19个原资源，其启用形状均为SphereCollider。混合机关保留包围范围，未声称所有形状已精确还原。
- 慢速纵向运动不再被旧“总位移不足12px即归零”规则吞掉，而按拟合残差判断。短时遮挡/曲率和正弦轨迹仍保留。
- 基础蜘蛛入场下落/回弹后停住，直接外推瞬时纵向速度会把站立安全位置误报为危险，导致翻到蜘蛛停留处。非稳定周期蜘蛛采用停留纵向先验，实际测量速度仍记录。该先验不是板子定时脚本。
- 弹球使用分段重力和落地反弹；`vision-object-priors.json`只保存全疾风配置的统计先验（上/下加速度中位8，反弹速度中位7），不读取运行板号。视觉拟合当前速度，并用上升段能量修正个体反弹冲量。重定时预测同时推进反弹后的速度，避免旧速度跨反弹继续使用。
- 简单危险继续原动作比较；观察到弹球时启用约0.96秒beam搜索，允许合法换边、跳跃、二段跳。只执行第一步，每帧用新画面重规划。扫掠检测覆盖两预测帧之间的穿越，保留输入延迟/定位余量。角色/机关的真实碰撞、伤害和物理仍全部由原客户端执行，策略几何只是近似预测。
- `tools/run-arena-vision`默认使用独立YOLO环境及 `vision-detector.json`固定模型摘要。保留新目录日志/源码SHA、独立验收和原暂停菜单收尾，无新增游戏菜单选项。
- 后续核对将剩余决策计算耗时也计入输入时刻外推，廉价反应与弹球搜索分别保留最近32次耗时的P90，避免昂贵计算被大量廉价帧稀释。同时修复外推只推进位置、未推进换边完成/落地状态的问题：未来已落地时应清零跳数，下一次输入不能仍按二段跳规划。规划和运行外推复用同一状态推进函数。
- `arena_yolo_tracking.py`新增离线同类/平面几何轨迹验收，拒绝原ID中途缺失/瞬移的池复用样本，远期比较只统计相机稳定子集。原坐标仅用于这个离线验收，未接入实时策略。

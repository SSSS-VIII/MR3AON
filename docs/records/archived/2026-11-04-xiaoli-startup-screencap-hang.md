# 小鲤清晨启动时截图阻塞

## 现象与依据

小鲤 06:31:52 调用游戏 start，06:41:52 到达外层 600 秒期限被回收。原生框架日志表明设备截图子进程一直没有返回，直到外层终止时才报错；与前一天显示 socket 缺失不同。

06:41:53 第二次 start 在读取 `sys.boot_completed` 时 20 秒超时。随后 status 判断 ready，但实际截图仍超时，说明会话在线与真实设备指令可响应不能等同。

06:43:06 stop，06:43:08 start，06:44:40 返回 ready 和截图。06:48:49 小鲤向主人报告恢复和饭团操作完成，随后主动停止游戏。维护排查时设备已关闭。

## 处理与边界

本轮仅核对已有会话、私有启动日志和框架日志，没有再次开机、操作游戏或修改 MR3A 运行逻辑。已定位为设备截图/响应阻塞，现有资料不足以确定 Android 或图形服务内部原因，不能声称根治。

小鲤工具原来把私有日志文件编号返回给模型，且工具说明、预设及指南要求转述编号，造成主人收到冗长维护信息。对应修复在 xiaoli 仓库独立提交：编号保留后台，模型只获得简短错误；同步清理维护者先前添加的编号转述要求，保留小鲤自己的历史记录。Python 34 项、Node 13 项相关检查通过，不为验证重放故障或打断游戏。

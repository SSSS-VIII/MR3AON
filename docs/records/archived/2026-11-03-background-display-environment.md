# 后台启动读取当前桌面显示连接

## 现象与原因

主机重启后，小鲤在 19:31、19:33 启动游戏失败。实例会话日志显示默认 `wayland-0` 不存在。实际桌面使用 `wayland-1`，用户 systemd 管理器已经记录正确连接，但开机较早启动的 qqbot 进程没有 `WAYLAND_DISPLAY`。

原入口 `systemd-run --setenv=WAYLAND_DISPLAY` 从调用者复制环境，覆盖了管理器里的当前值，导致无窗口启动仍无法建立 Android 会话。并非账号、任务配置或模型判断问题。

## 改动

会话启动前核验显示 socket：优先保留调用者仍有效的连接，否则读取用户管理器的当前环境。将核验后的显示地址和 runtime 目录显式传给会话服务。没有有效连接时立即报错，不盲等两分钟。仍复用原命名实例、账号和启动任务，不打开游戏桌面窗口。

## 验证

- `tests/test_waydroid_instances.py tests/test_instance_runtime.py tests/test_named_instances.py`：41 passed；覆盖早启动缺少变量、过期变量、有效显式地址及无可用连接，并检查实际服务命令携带所选值。
- 使用小鲤原 `game_control start` 冷启动，返回 `ready` 及 1280×720 截图，启动任务正常结束并交还控制权。
- 排查中通用截图助手会先调用默认带窗口的 `ensure_ready`，该尝试等待平台服务超时；随后直接调用已有会话的只读 `screenshot` 获取画面。未改动其它实例、账号配置及小鲤提示词。
- 本轮未再次重启整台主机；复现入口使用的调用者与故障时一致，缺少显示变量，管理器中已有有效桌面连接。

## 后续：手工停止提示已有控制者

用户随后执行 `./run xiaoli --stop` 遇到控制者互斥。只读核验发现小鲤通过自身游戏控制器再次发起了启动，启动器正在持有该实例的真实控制锁，并非可以直接删除的残留文件。普通 `shutdown()` 使用非接管控制租约，故与正在启动或输入的请求冲突时会拒绝；小鲤的工具启停入口则在生命周期操作前封装了显式接管。此轮仅核验和解释，未强停进程、改变停止策略或修改小鲤提示词。

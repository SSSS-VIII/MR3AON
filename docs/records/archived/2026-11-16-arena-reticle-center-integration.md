## 需求与当前状态

独立CPU模块已经主任务审查并提交为 `3e4871b`，对应[独立模块记录](2026-11-16-arena-reticle-center.md)。本次只补附加字段适配和竹子内部消费，方便分别回放；未连接实际检测器，未启用默认运行，未做原生验收。没有修改 `ObbDetector`、phase分类器或runner，避免与其它实验混改。

## 改动与字段边界

`arena_reticle_center.refine_bamboo_cues(refiner, bgr, cues)`仅按`motion_kind=bamboo`提取原顺序box，调用独立模块，再对cue的副本附加：

```text
center_refinement = {
  version: 1,
  space: "screen_640x360",
  center: [cx, cy] 或 null,
  reason: null 或拒绝原因,
  evidence: 模块返回的候选证据
}
```

原box对象、phase、confidence和非飞竹cue均保留；none/uncertain阶段仍参与像素歧义检查。拒绝结果覆盖上一帧可能遗留的精修字段，不丢掉该cue。计数或索引顺序不符时报错，防止结果错配。

`BambooClocks.observe`仍先对原box做既有`reticle_tracking_box`规范化及8px去重。去重后，仅在内部cue副本上消费合规的绝对屏幕中心，保留规范框宽高。缺字段、拒绝、空间/版本不符、非有限/非法坐标均保持该帧原规范框；不冻结旧时刻屏幕坐标。

不能先改原box后再调用裁剪规范化。例如原框`(10,60,40,30)`精修至中心`(30,70)`，若先重定位再规范化，y=55会误触顶部裁剪规则，错误变为中心65；正确顺序是先规范原框，再绝对重置为70。相机参考只沿既有Track.history/target_samples减一次，未在精修层提前扣除。

当前目标Y仍沿既有3样本中位数，原launch/phase公式不变。接受与拒绝切换可能影响短轨迹/关联及中位数，后续完整回放必须分别报告；单帧定位改善不代表整个时钟或无伤改善。

## 主任务接线与完整回放结论

随后主任务在phase分类后增加显式`center_refiner=None`接线、perception CPU统计及runner模型选项/纹理SHA记录，默认关闭。source清单纳入模块与配置。先期XY重定位版本回放出现关联碎片和发射匹配门限退步，因此已撤下该消费方式。

最终实现只把合法精修Y用于选定track.last_cue后的target_y/target_samples；原框、去重、关联history、速度和事件身份均保持原规范几何。绝对中心helper仍用于校验与取Y，不把精修中心回写轨迹框，不改phase裁图。已有实体链接后仍沿原attack_y更新规则。

六＋二回合2405帧CPU回放：关闭路径逐点相同；只输入cue时，除target_y/target_samples外事件、原轨迹/history、lock/fire逐帧完全相同。包含observe_attacks后，本缓存内attack_links、事件和时钟签名也相同，但不保证其它数据恒定。目标Y绝对误差P95整体4.184→3.903px，接受子集3.670→1.929px；0/.2/.4秒裸全XY覆盖511→537、157→300、116→271，现有MPC裕量覆盖837→842、774→779、788→788。保留1次.4秒裸覆盖退步及接受/拒绝切换目标抖动增大，未作全局不退步声明。

研究结果在ignored `center-refinement/integration/仅目标Y接入回放.md`、`target-only-study/compact-comparison.json`。主任务新增phase先于中心的原框保护与身份不变测试，59项聚合CPU保护通过。v42/v43实际center关闭，不能算开启后的原生验证；开启实验仍待独立闭环。

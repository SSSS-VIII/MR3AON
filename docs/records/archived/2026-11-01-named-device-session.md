# 按名字持久管理 Android 环境与设备会话

## 现象 / 需求

用户只提供一个名字，内部负责 Waydroid、ADB、配置隔离和生命周期；同名必须完全复用，不同名账号/密码独立。默认环境保留当前账号。后续大小号协同及 dsh 封装需要稳定的按名设备对象，但本次不开发智能体服务。

## 原因

旧工具向调用者暴露 slot 和端口，默认 Waydroid 又不经过实例管理。仅有独立容器不足以保证脚本、恢复检查或未来智能体始终操作同一账号。

## 改动

- 新增 `runtime.InstanceRegistry`，持久化名字到内部 slot 的映射，文件锁串行分配；名字支持中文、字母、数字、下划线和短横线。注册表损坏、重复编号或与已有实例身份不符时拒绝连接，不自动换账号。
- `main` 固定接管现有默认 Android 和 `deps/bin/config`，复用原数据，不重建、不搬迁账号。低层管理工具增加内部 slot 0，默认环境的启动/状态/停止也纳入同一管理入口。
- 附加名字的配置、状态、日志、数据位于 `.mr3a-instances/<名字>/`，目录不入库。新环境只初始化空任务配置，不复制主账号输入、密码或完成状态；同名再次准备不覆盖配置。可写缓存/题库复制初始数据，资源和程序不复制。
- 实例身份与配置采用原子写入和私有权限。默认环境旧 pip 配置保留；主奖励图提供受控迁移合并，同名文件冲突保留两个版本，原文件不删除。该合并在后续 launcher 持有控制权时执行。
- 新增 `InstanceSession(name)` 的状态、就绪、重启、截图、按键与点击能力。目标地址在内部按该实例状态解析，连接和授权自动完成；截图先写 Android 临时文件再读取，避免既有 amdgpu 输出污染 PNG。
- `control()` 提供实例级排他控制租约，输入方法要求持有租约；截图不需要控制权。同名旧版主脚本也会被识别，避免同时控制主账号。租约 fd 可跨 exec 保留，供后续 launcher 使用。
- 本提交为实例注册/设备层功能；run 入口和 Agent 路径接入分别提交，不包含鬼族改动。

## 验证

- 核心实例/Waydroid 测试 22 项通过：持久复用、空白凭据、独立资源、控制租约、非法名字、注册表损坏/换绑拒绝、主奖励迁移不丢图、默认环境接管等。
- 使用 `InstanceSession('main')` 与 `InstanceSession('small')` 分别取得真实 1280x720 PNG，无需调用者管理端口；读取截图前后主 PiCli 配置 hash 不变。
- `main` 当前旧运行进程（包括二进制已被重编后标记 deleted 的情况）可识别并拒绝第二个控制者。
- 本机 `small` 复用先前创建的第二个 Android；两个窗口仍保持运行。没有复制主账号登录信息或安装游戏到小号，也未实现协同业务/智能体服务。

## GitHub check 的根因与修复

失败运行 [43848042344](https://github.com/SSSS-VIII/MR3AON/actions/runs/43848042344) 在 maa-checker 步骤退出，后续原生加载及 Schema 尚未执行。取到的 1.2.7 源码中，`checkTask` 将每个节点的全部 `task.next` 引用合在一个 Set，未区分 `next` 和 `on_error`，所以共享终止/恢复目标被错误标成 Duplicate route。

本地复现还包含后续新增的更新重启、诊断截图兜底，共 8 条误报。没有为通过检查删除业务错误出口或额外插入无意义跳转节点。固定 maa-checker 为实际验证的 1.2.7，只关闭其 `duplicate-next` 规则；新增 `tools/ci/check_routes.py` 独立检查每一个 `next` / `on_error` 列表（含任务选项 override），同一列表的重复目标依旧失败，跨两个列表共享目标合法。其它 maa-checker 检查、原生加载和 Schema 验证继续执行。工作流也补充 requirements 和 Schema 文件变动触发。

离线验证：路由替代检查及深渊/跨周恢复共 43 项通过；maa-checker 剩余规则通过；整包原生资源加载、Pipeline/Interface/任务 JSON Schema 验证与 diff 检查通过。本轮未启停任何游戏实例。

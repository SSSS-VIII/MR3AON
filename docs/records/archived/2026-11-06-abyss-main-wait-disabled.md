# 主环境深渊未挂起的配置与状态排查

## 现象

用户截图显示 AgentSchedulerWait 等待通灵巡逻，深渊挑战没有20:00延后标记，实际未进行深渊战斗。

## 原因与证据

- main 保存的深渊选项 `挂机等待至深渊挑战开启` 实际为 `No`。接口默认 Yes 不会覆盖已有账号保存的 No。
- 2026-11-06 12:37:02 提交深渊任务，12:37:06 写入顶层禁用至2026-11-07 05:00，并经 `深渊挑战完成停止任务` 返回调度。这对应关闭等待时提前跳过的出口。
- 13:07 本次重启的 bootstrap 又从持久化状态读取深渊为禁用候选。当前磁盘状态与日志一致。
- `refresh_if_needed` 在当前运行实现中仅跨每日重置周期重载磁盘，正在运行的任务配置和跳过状态均已进入内存。只在磁盘改选项不足以恢复当前会话的今晚调度，直接在线删除状态还可能被内存旧值重新写回。

## 语义纠正与后续

用户随后澄清 main 的 No 控制旧原地长挂机，配置符合预期。此前将其解释为关闭 Agent 延后调度，并建议开启该选项，是错误的。实现需要将周五20:00的调度门独立于旧开关。

已修正代码，验证与会话交接见 [调度与挂机分离](2026-11-06-abyss-scheduler-independent-of-idle.md)。当前会话中的误写跳过状态需要在停止会话后清理，仅改选项不能解决此问题。

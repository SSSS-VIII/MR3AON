# 保持拓扑语义的规划端点相接检查优化

## 原因与改动

v121对实际保存的坡面、飞竹、五关MPC状态做CPU profile，反复connected_height检查占明显开销；飞竹三次choose中约2.63万次np.linalg.norm，每次只算两个二维端点。改为标量平方距离，仍使用原6px阈值；边界36±1e-9及非有限值回退原NumPy规范，避免浮点边缘或NaN顺序语义变化。不改搜索规模、成本、动作/物理/任何决策参数。

## 验证

5项新保护含2000随机端点、30方向×5近阈值、NaN/Inf原顺序、绳/坡/缝隙/浮台及不同未来时刻，和原实现逐项比较。全部arena726通过/2依赖跳过。

v123无profiler、无GPU/设备，以39坡面+41飞竹+40五关保存状态做交替新旧各3次，120状态共720次选择全部一致。飞竹中位23.97→19.46ms/P95 31.47→25.77；五关22.41→18.04/P95 37.84→30.86。单段坡面几乎不调用多段相接，18.14→18.83/P95 29.53→29.89，未将该组计成改善。只是冻结状态CPU测量，尚非新的实机链路成绩，后续原生继续核验。

profile、完整逐状态时间/动作及基线source取HEAD证据保存在ignored render-readback-probe/mpc-profile-v121.json、support-join-v123.json及脚本；没有为了变快降低检测/碰撞质量。

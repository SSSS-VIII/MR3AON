# 启动游戏登录前是否会点渠道弹窗 X

## 需求

用户要求检查启动游戏到看到登录按钮之前，脚本是否会点击 X 关闭渠道服弹窗。

## 原因 / 检查范围

静态追踪启动游戏 entry、启动主循环、登录识别、活动弹窗节点及 Python 弹窗守护；未在正在使用的账号页面运行脚本或实际点击。

## 发现

- `启动游戏entry` 经 `[JumpBack]启动流程` 进入主循环。`启动流程.next` 同时包含「识别登录」及「处理登录活动弹窗」，后者不以进入游戏主页或先点过登录按钮为前提，所以登录按钮出现前也可能执行关闭动作。
- 「处理登录活动弹窗」在逻辑分辨率下的 ROI `[833,5,440,441]` 匹配 `叉叉0.png` 至 `叉叉3.png`，green_mask=true，命中后 Click 识别位置。它不是全屏任意找 X，也没有直接判断渠道类型、前台应用或弹窗用途。
- 因此：渠道提示/广告的右上 X 若匹配模板，会尝试关闭；渠道账号/授权窗口的 X 若位置和样式同样匹配，也存在被关闭的可能。左上 X、超出 ROI 或不同样式不会由该节点处理。是否实际关闭某个具体渠道弹窗，不能只靠静态代码保证。
- 「识别登录」在候选序列中优先于该关窗节点；若弹窗背后登录按钮仍可匹配，可能先走登录识别路径，因此不能宣称全部渠道弹窗都会自动消除。
- 固定点击 `[1252,38]` 的「点击空白处关闭未知签到」另由主页聊天/集会所验证失败分支触发，不能当作初始渠道弹窗专用处理。
- Python `popup_watchdog.py` 的两个 Agent 注册装饰器均注释，项目未见主动 maybe_tick 调用；本次相关关闭行为来自流水线，不是后台守护额外全屏点 X。
- 全局错误恢复的「处理叉叉弹窗」也是右上模板匹配，额外包含叉叉4，但那属于错误恢复链，不等同于正常启动前阶段的独立渠道支持。

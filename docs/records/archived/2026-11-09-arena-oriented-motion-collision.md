# 视觉旋转框的角速度与碰撞预测

## 需求与原因

原爪、刀、钩和电线等有旋转矩形碰撞体；仅预测包围AABB会把空角当成障碍，不能保留原碰撞形状。新增标准YOLO OBB监督后，需要让已有经典跟踪与滚动规划接收四角，不能另写神经网络。

## 改动

- Detection/Track保留可选quad、原资源、collider_shape；用有界历史拟合模π角速度，近正方形模π/2，残差过大回到零角速度。
- 遮挡、相机参考位移、时间外推同时移动四角，复合机关的球和线不混配。
- 短时策略用角色胶囊与旋转矩形距离；滚动搜索用相邻帧相对凸包扫掠及转角弓高包络，保留纵横不确定性，防止穿隧和AABB空角误报。
- 未提供四角时沿用旧路径；NPC Capsule仍是保守包围矩形，不能声称完整胶囊精确碰撞。默认v4没有提供quad，尚未部署新OBB模型。

## 验证与限制

6项新测试覆盖跨规范角、相机位移遮挡、球/线身份、胶囊圆角、扫掠穿隧、真实Reactive/MPC调用；全arena **209通过、2依赖缺失跳过**（Crypto/UnityPy）。

原生验证帧只用于离线拟合核验，不输入部署策略。刚性连续可见样本中，钩type104的0.2秒角误差中位3.87→1.75度，P90 5.15→2.35度；武士type211的突发攻击仍约24度中位、59度P90，恒角速度不能预知攻击状态变化。审计在忽略目录`native-rotation-audit.json`。静止爪存在轻微抖动，不能把此审计当作神经网络检测或实机跑图通过。后续须接入视觉四角、补数据并实机验证。
